## 实验 1：软编码 vs 硬编码的可学性

**脚本**：`scripts/probe_alias_soft.py`
**问题**：把真实标签映射到别名块时，「块内均匀软分布」是否比「块内随机 pick 硬别名」更可学、且逆映射无损？

### 数据

| 配置 | 逆映射后精度（块内求和 argmax） | 相对基线损失 |
|---|---|---|
| 基线（真实标签） | 0.9514 | — |
| K=2 硬编码（块内随机 pick） | 0.9443 | −0.0071 |
| **K=2 软编码（块内均匀）** | **0.9471** | −0.0043 |
| K=4 硬编码 | 0.9271 | −0.0243 |
| **K=4 软编码** | **0.9500** | **−0.0014** |

### 结论

1. **软编码在所有 K 下都优于硬编码**，K=4 时软编码几乎无损（0.9500 ≈ 基线 0.9514）。
2. 原因：硬编码的「块内随机 pick」使目标不可预测（同类样本 pick 不同别名），模型无法稳定学习；
   软编码的「块内均匀」使目标重新成为「类别的确定函数」，只需学块归属。
3. **逆映射可复用** `别名 // K`（argmax 落在块内），无需逐样本记录。

### 核心代码

**软标签损失（KL 散度形式）** — `scripts/probe_alias_soft.py:40-45`

```python
if targets.dim() == 2:
    # soft target: KL divergence with log-softmax
    logProb = torch.log_softmax(logits, dim=1)
    loss = -(targets * logProb).sum(dim=1).mean()
else:
    loss = torch.nn.functional.cross_entropy(logits, targets)
```

**块内求和逆映射** — `scripts/probe_alias_soft.py:76-77`

```python
blockSums = torch.stack([probs[:, c * K:(c + 1) * K].sum(1) for c in range(CLASSES)], dim=1)
hardInv = float((blockSums.argmax(1) == testTrue).float().mean())
```

## 实验 2：结构化扰动的 argmin 度量

**脚本**：`scripts/probe_gradient_perturb.py`
**问题**：标签通过 `gradientB[i] = softmax(logits_i) - onehot(y_i)` 泄露，其 **argmin 就是标签维度**。
零均值高斯噪声不改变 argmin（期望），因此无效。哪种**改变方向**的结构化扰动能切断 argmin 信号？

### 数据

| 扰动 | argmin 恢复标签 | 梯度相关性（信号保留） |
|---|---|---|
| 无扰动 | 1.0000 | 1.0000 |
| 零均值高斯 scale=0.5 | 0.9995 | 0.9017 |
| 符号翻转 p=0.5 | 0.4875 | −0.0250 |
| 符号翻转 p=1.0 | 0.0000 | −1.0000 |
| 标签维度置零 | 1.0000 | 0.4478 |
| **类中心去除** | **0.1185**（< 随机 0.125） | **0.2653** |
| 标签维度取反 | 0.0000 | −0.5932 |

### 结论

1. **零均值高斯确认无效**：argmin 恢复率 0.9995（标签几乎完全可读）。
2. **符号翻转隐藏了标签但摧毁学习**（相关性 −0.025，B 完全无法学习）。
3. **类中心去除是唯一有前景的**：argmin 恢复率 0.1185（**低于随机 0.125**），同时保留 0.2653 的相关性。
   因为标签信息主要在「类间均值差」里，减掉每类平均梯度后 argmin 不再能定位标签。

### 核心代码

**argmin 恢复度量** — `scripts/probe_gradient_perturb.py:36-37`

```python
def argminRecovery(grad, y):
    return float((grad.argmin(1) == y).float().mean())
```

**类中心去除（结构化扰动）** — `scripts/probe_gradient_perturb.py:69-73`

```python
# class centering (subtract per-class mean)
g = grad.clone()
for c in range(C):
    m = (y == c)
    g[m] = grad[m] - grad[m].mean(dim=0, keepdim=True)
```

## 实验 3：类中心去除的完整验证

**脚本**：`scripts/probe_class_centering.py`
**问题**：argmin 度量只说明「标签难以直接读出」。完整模拟 B 学习 + 攻击者补全后，
类中心去除对「主任务精度」与「攻击者恢复率」的实际影响如何？

### 数据

| 扰动 | 主任务精度 | 攻击者恢复率 |
|---|---|---|
| none | 1.0000 | 1.0000 |
| gaussian | 1.0000 | 1.0000 |
| **center（类中心去除）** | **0.8090** | **0.6770** |

### 结论

1. 类中心去除**确实降低攻击者恢复率**（1.0 → 0.677，−0.32），但**未到随机 0.5**。
2. **代价是主任务精度下降**（1.0 → 0.809，−0.19）。
3. **它是「精度-隐私权衡」型机制**，不是重指派那种「无损置换」。
   对比：重指派 = 无损 + 到随机；类中心去除 = 有损（−0.19 精度）+ 不到随机（0.677）。

### 核心代码

**类中心去除 + B 反向传播返回信号（真实 VFL 机制）** — `scripts/probe_class_centering.py:34-46`

```python
if perturb == "center":
    signal = grad.clone()
    for c in range(CLASSES):
        m = (truth == c)
        signal[m] = grad[m] - grad[m].mean(dim=0, keepdim=True)
elif perturb == "gaussian":
    rms = grad.pow(2).mean(dim=1, keepdim=True).sqrt().clamp_min(1e-12)
    signal = grad + 0.5 * rms * torch.randn(grad.shape)
else:
    signal = grad

# B back-propagates the RETURNED signal (this is the actual VFL mechanic).
logits.backward(signal)
```

## 三个实验的联合结论

| 实验 | 核心发现 |
|---|---|
| 1 | 软编码（块内均匀）修复硬编码的精度暴跌，K=4 几乎无损 |
| 2 | 零均值高斯无效；类中心去除是唯一能切断 argmin 标签泄露的结构化扰动 |
| 3 | 类中心去除是「精度-隐私权衡」（精度 −0.19，攻击者 −0.32 但不到随机），不如无损的重指派 |

**方向判断**：类中心去除作为「结构化扰动」是三者中唯一有前景的，但它是权衡型，
需要真实 VFL 验证（真实设定下攻击者恢复率不是玩具的 1.0）。已实现为
`gradientClassCenterStrength` 参数（`defense/purified_vfl.py`）。
