# 任务流程（当前）

> 建立于本阶段最后，用于固定执行顺序。此前因**并行运行**与**跨版本比较**导致多次误判，
> 本文档把流程写成强制条款。

## 一、强制操作规则

1. **串行执行**：任何时刻只允许一个训练/评测进程运行。启动前必须先扫描进程，
   发现已有 `grid.py` 或 `run_variant_snapshot.py` 在跑就**不启动**，等它结束。
2. **跑完一个再跑下一个**：一个试点完全结束后，才清理产物、启动下一个。
3. **启动前核对时间戳**：打印所有相关源文件的修改时间与当前时间，
   确认 `修改时间 < 启动时间`。运行中的 Python 进程不会重新加载模块，
   改代码对已运行进程无效——本项目为此损失过整批结果。
4. **不手写参照值**：所有基线数值必须由脚本从 `outputs/three_variants/o/` 等
   存档中直接读取，不得手工抄录。曾因把 `dataset_03` 的数字抄到 `dataset_02`
   那一行而误判"基线不复现"。
5. **试点只判方向**：5 场景试点可以回答"机制是否有效"，**不能**回答"分数是多少"。
   凡是会影响三项分数的结论，必须走全量 40 场景。
6. **参数改动的量级判据**：公式分变化 ≥1 才有可判断的迁移性；<1 的变化
   与平台无关（第 64 轮结论）。
7. **不依赖本地 LRA 改善**：平台/本地比值 性能 0.9941、鲁棒 0.9896 可信；
   隐私 0.8098 不可信。直接调优本地标签恢复率的改动系统性负偏约 -2.1
   （候选 p 与 cc_ramp100 的实测）。

## 五、待决策事项

1. **PG 的 `partyDropoutRate=0.3` 是否安全**：O 用的是 0.2，而此前实测 0.2 已越过
   `d04_pmc` 的阈值（`Q_p` 1.0 → 0.0）；0.3 需全量确认不伤其他场景。
2. **`labelAliasFactor` 是全局参数**：设为 2 会让**全部**场景的输出维度从 2 扩到 8，
   属全局架构改变。若 PF 有效，需确认这让所有场景都不劣化。
3. **core 改动的合规性**：`labelTransform` / `predictionTransform` 两处接缝已获
   "可以修改 A 方本地"的确认，但提交物是否需只含防御代码仍未确认。
