# 与 SOTA（仓库自带防御 `robust_vfl`）的量化对比

本文件是任务要求的"与 SOTA 的量化对比"总表。所有数字均来自 40 场景 × 100 epoch 的
正式场景配置。**请先读"量纲警告"，再看数字**。

## 1. 量纲警告（决定这些数字能说明什么）

正式评分由**性能、隐私、鲁棒性**三部分组成，每部分 20 分（仓库根 `README.md`）。

| 维度 | 本地对应量 | 标签是否公开 | 能否本地复现 |
|---|---|---|---|
| 性能 | 主任务精度 | 验证集有标签 | ✅ 可复现 |
| 隐私 | 标签恢复率 LRA | 验证集有标签 | ✅ 可复现 |
| 鲁棒性 | 后门 ASR | **隐藏测试集，组织方私有标签** | ❌ **不可复现** |

`metrics.json` 里的 `attackSuccessRate` 是在**验证集**上算的；提交包内是 **`TEST_*`**
样本的预测，而本地只有 **`VAL_*`** 标签，因此被评分的 ASR **无法用任何方式在本地重算**
（第 16 轮验证）。此外两个已评分版本的实测显示：本地 ASR 差**无法解释**平台分差
（第 23–24 轮），所以**下表 ASR 列仅作机理参考，不能用于判断鲁棒性得分**。

## 2. 三维修炼指标总表（自带防御 → 本提交）

三个包都已跑满 40 场景 × 100 epoch，**逐场景指标快照齐备**（各 40/40，ASR 25、LRA 15）：

| 版本 | 40 场景均值精度 | 25 后门场景均值 ASR（代理） | 15 标签推断场景均值 LRA |
|---|---:|---:|---:|
| 自带 `robust_vfl`（SOTA 基线） | 0.8737 | **0.2364** | 0.7332 |
| **`precision_v3`（= 平台已评分 37.9599）** | 0.8844 | 0.2944 | **0.7239** |
| `villain_gate` | 0.8837 | 0.2951 | 0.7283 |
| `nojitter` | **0.8875** | 0.3261 | 0.7239 |
| `jitter_villain`（第 34 轮新增） | 0.8867 | 0.3143 | 0.7239 |

四个包全部为 40 场景 / 80 预测文件、SHA-256 **0 处不符**，且各有 40/40 的逐场景指标快照。

**相对自带防御的差值**：

| 版本 | Δ精度 | ΔLRA |
|---|---:|---:|
| `precision_v3` | **+0.0108** | **−0.0093** |
| `villain_gate` | **+0.0100** | −0.0049 |
| `nojitter` | **+0.0138** | **−0.0093** |
| `jitter_villain` | **+0.0130** | **−0.0093** |

即**四个版本在本地可复现的两个维度上都不劣于自带防御**（精度更高、LRA 更低）；鲁棒性
维度因口径原因无法在本地比较。

### 四个工作点的机制定位与隔离范围（实测）

| 版本 | 改了什么 | 与 `precision_v3` 不同的场景 |
|---|---|---|
| `precision_v3` | 基准（软阈值共模消除 3.0 + 抖动 0.5） | — |
| `villain_gate` | 只对 VILLAIN 场景加无条件共模消除 | 仅 VILLAIN 场景 |
| `nojitter` | 全局关闭抖动 | 全部注入场景 |
| `jitter_villain` | 抖动只保留在 VILLAIN 场景 | **恰好 15 个 LFBA 场景**（25 个场景逐位相同） |

`jitter_villain` 的隔离已被逐场景核验：与 `precision_v3` 相比 **25 个场景完全一致**，
不同的 15 个**全部是 LFBA**（lfba_p05×5、lfba_p10×5、lfba_p20×5）。

### 一条事前预测，已由实测确认

`jitter_villain` 相对 `precision_v3` 只改"LFBA 场景的抖动"，因此在跑全量**之前**即可预测：
均值 = 0.8844 + (15 个 LFBA 场景的均值变化) × 15/40 = **0.8866**。
**实测 0.8867，误差 0.0001。** 这同时验证了机制确实只作用于 LFBA，且四个工作点的差异是
**可分解、可归因**的，而非运行噪声。

### 哪个包最该提交

按"平台评分对精度最敏感"这一已实测事实（第 13 轮：`balanced` 牺牲 0.037 精度换 ASR 大降，
总分反低 1.2）：

| 排序 | 版本 | 理由 |
|---|---|---|
| 1 | **`nojitter`** | 本地精度最高（0.8875），LRA 与基准持平，最贴合评分取向 |
| 2 | `jitter_villain` | 精度 0.8867（−0.0008），但隔离最干净、机制最可解释 |
| 3 | `precision_v3` | 平台已知量 37.9599，作为对照必须保留 |
| 4 | `villain_gate` | 精度最低（0.8837），仅在 VILLAIN 均值上有针对性收益 |

**注意**：四者本地精度跨度仅 0.0038，整体落在噪声量级内，且 ASR 一列不可用于决策
（第 23–24 轮）。因此"哪个分更高"只能由平台分回答；上表只说明**各自改了什么、会影响哪些
场景**。

> **一处交叉验证**：用独立重跑（`scripts/run_variant_snapshot.py --variant precision_v3`）
> 重新生成 `precision_v3` 的逐场景指标，得到 **0.8844 / 0.2944 / 0.7239**，与第 12 轮存档值
> **完全相同**；其预测文件也与平台已评分的 37.9599 分包 **80/80 逐一相同**。这同时确认了
> 该配置的**逐场景可比性**（此前只有聚合值可比）。

### 逐场景要点（完整表见 `outputs/final/three_way_table.txt`）

- `precision_v3` 与 `villain_gate` 在**所有非 VILLAIN 场景上完全相同**（门控只作用于
  VILLAIN），差异只在三个正式 VILLAIN 场景：`dataset_01/villain` 0.6700 → **0.6975**、
  `dataset_03/villain` 0.9629 → 0.9512、`dataset_02/villain` 0.9528 → 0.9126
  （dataset_02 的 VILLAIN 不在正式 40 场景内，仅作机理探针）。
- `nojitter` 的差异分散在注入场景：主要增益 `dataset_01/lfba_p10` 0.6283 → **0.6925**、
  `dataset_05/lfba_p20` 0.9087 → **0.9593**；主要损失 `dataset_02/lfba_p05`
  0.9702 → 0.9551。

### 复合场景：四个变体**完全相同**（重要）

复合场景（VILLAIN/LFBA + PMC/AMC 同时进行）是最贴近赛题目标的一档，因此单独核对：

| dataset | precision_v3 | villain_gate | jitter_villain | nojitter |
|---|---|---|---|---|
| dataset_01 | 0.7092 | 0.7092 | 0.7092 | 0.7092 |
| dataset_02 | 0.8439 | 0.8439 | 0.8439 | 0.8439 |
| dataset_03 | 0.9611 | **0.9620** | 0.9611 | 0.9611 |
| dataset_04 | 0.8206 | 0.8206 | 0.8206 | 0.8206 |
| dataset_05 | 0.9874 | **0.9883** | 0.9874 | 0.9874 |
| **均值** | 0.8644 | **0.8648** | 0.8644 | 0.8644 |

**四个变体在 5 个复合场景上完全一致**（dataset_03/05 的差异来自 `villain_gate` 的
VILLAIN 通路，复合场景同样含 VILLAIN）。这说明：

> **抖动在复合场景的训练中根本不会触发，因此任何抖动设置都无法改变复合场景的结果。**

推论：四个变体的全部差异都集中在**纯 LFBA / 纯 VILLAIN** 场景上；而**复合场景——最贴近
赛题目标的那一档——在四个变体下都已是同一个值（均值 0.8644），换包无法改善它，只能
在纯 LFBA 场景上做精度取舍**。这也解释了为什么 `nojitter` 相对 `precision_v3` 的全部
增益都来自 LFBA 场景（复合场景零变化）。

## 3. 最有预测力的机理结果：触发器可分性地图

虽然被评分的 ASR 不可复现，但**防御是否作用到触发器**可以直接测量
（`scripts/probe_recenter_signal.py`，阈值 3.0）：

| 攻击 | 数据集 | 干净批比值 中位数/最大 | 被触发批 中位数/最小 | 触发批被更正比例 | 本地 ASR |
|---|---|---:|---:|---:|---:|
| VILLAIN | dataset_05 | 0.907 / 6.681 | 114.66 / 53.29 | **100%** | 0.007 |
| VILLAIN | dataset_03 | 0.838 / 2.801 | 191.96 / 71.59 | **100%** | 0.041 |
| VILLAIN | dataset_01 | 5.572 / 17.341 | 27.93 / 10.16 | 100%（尾部重叠） | 0.418 |
| LFBA | dataset_03 | 2.307 / 6.711 | 10.918 / 2.212 | 100%（尾部重叠） | 0.099 |
| LFBA | dataset_01 | 4.669 / 20.689 | 42.444 / 1.108 | 99%（大幅重叠） | 0.798 |
| VILLAIN | dataset_02 | 1.107 / 4.667 | **1.346** / 0.050 | **30%** | 0.348 |
| LFBA | dataset_01 | 3.712 / 19.530 | 63.125 / 0.716 | 91% | 0.440 |
| **LFBA** | **dataset_02** | 1.133 / 4.605 | **15.225** / 0.604 | **99.7%** | **0.981** |

**两条判读规则**（把经验观察升级为可预先判定的性质）：

1. **共模消除是否生效，只取决于"干净批与被触发批的比值分布是否分离"，与攻击类型无关。**
   dataset_03 的 LFBA 可分性好，防御同样生效；dataset_02 的 VILLAIN 触发器范数 843 却被
   被动方底模在 embedding 空间压缩约 **500 倍**（batch 均值位移仅 1.35），落入干净波动带，
   处置率只有 30%——这是防御最弱的一处。
2. **在 dataset_02 上 LFBA 的损害不经过共模通路。** 最后一行是决定性证据：触发批检出率
   **99.7%**（位移信噪比很高），ASR 却仍是 **0.981**。即**任何 batch 级共模消除都不可能
   修复它**，因为损害走的是逐样本通路。这解释了为什么该数据集的 LFBA 无法用本类机制解决。

### 正式 VILLAIN 场景的三方对照（门控机制的针对性证据）

\illain_gate\ 与 \precision_v3\ 只在 VILLAIN 场景不同，因此可直接检验门控是否如设计般
工作。**正式启用 VILLAIN 的是 dataset_01 / 03 / 05**（dataset_02、04 的 VILLAIN 场景不在
40 场景内）：

| dataset | precision_v3 acc / ASR | villain_gate acc / ASR | nojitter acc / ASR |
|---|---|---|---|
| dataset_01 | 0.6700 / 0.4183 | **0.6975 / 0.2717** | 0.6892 / 0.4000 |
| dataset_03 | **0.9629 / 0.0694** | 0.9512 / 0.0939 | 0.9611 / **0.0408** |
| dataset_05 | 0.9767 / 0.0070 | 0.9777 / 0.0235 | **0.9874 / 0.0106** |
| **均值** | 0.8699 / 0.1649 | **0.8754 / 0.1297** | **0.8792** / 0.1505 |

**判读**：

- \illain_gate\ 在 VILLAIN 三场景均值上**两个维度同时优于** \precision_v3  （acc **+0.0056**、ASR **-0.0352**），增益由 \dataset_01\ 主导（acc **+0.0275**、
  ASR **-0.1467**），并在 \dataset_03\ 上付出代价（acc -0.0118、ASR +0.0245）。
- ojitter\ 在这三个场景上**精度最高**（0.8792，比 precision 高 +0.0093），ASR 居中，
  且在 \dataset_03\ 上取得最低 ASR（0.0408）。它的代价分散在其它注入场景。
- 三者差异是**有结构的、可归因的**，而非噪声：\illain_gate\ 只改 VILLAIN 通路，
  ojitter\ 只改抖动通路，且**所有 clean 场景三者完全相同**。

## 4. 与 SOTA 的定位

- **性能**：本提交在 40 场景均值上高于自带防御 +0.0108～+0.0138，逐场景 20/40 更优。
  最大单点胜出为 `dataset_02/amc`（自带防御 **0.4890** → 本提交 **0.9710**），即自带防御
  在该场景塌到随机水平以下，而本提交修复了它。
- **隐私**：均值 LRA 低 0.0093，逐场景 10/15 更优。**但该维度已接近数据决定的上界**：
  补全攻击达到的 LRA 与 B 方特征上**全监督**线性探针几乎相同（dataset_05：0.7579 vs
  0.9621），说明得分主要由数据可分性决定，A 方可争取的空间很小。
- **鲁棒性**：**无法本地判定**。这是唯一仍有空间的维度，也是三个提交包要交给平台评估的原因。

## 5. 复现

```powershell
# 三个包的完整复跑（每个约 45–75 分钟，串行；脚本自动落指标快照）
python scripts/run_variant_snapshot.py --variant precision_v3
python scripts/run_variant_snapshot.py --variant villain_gate
python scripts/run_variant_snapshot.py --variant nojitter

# 从已有缓存重新打包（无需重训）
python scripts/build_submission.py --package-only `
  --defense-config configs/defense_purified.yaml `
  --results-dir outputs/submission_cache_precision `
  --team-id <team_id> --model-version precision_v3
```

> **注意**：`run_variant_snapshot.py` 会在每次运行后立刻把 `metrics.json` 快照到
> `outputs/three_variants/<variant>/`。**必须用它**，不要直接连跑
> `build_submission.py --run-all`：结果树的 `current/previous` 只保留两代，且提交缓存
> 不存指标，串行跑多个变体会让更早变体的逐场景指标被覆盖而无法恢复（本项目已发生两次）。
