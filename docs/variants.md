### v5 暴露的一个实现级缺陷（已修）

首次跑 v5 时在 `dataset_04/lfba_p05` 直接崩溃：

```
ValueError: LFBA cannot calculate L1 similarity from zero gradients
```

LFBA 用 L1 梯度相似度构造投毒集，**任一逐样本梯度为零**就抛异常，导致整个场景无结果。
重指派会把某样本的梯度换成"捐赠者"的梯度，捐赠者为零时接收者即为零。

排查：输入侧判据（不捐赠零梯度）仍崩溃；改用 `scripts/probe_gradient_health.py` 在真实
流程插桩，实测**仍有 5 行 L1 为零**。最终改为**对输出强制不变量**——凡输出行 L1 非正，
补一个 `1e-11` 的严格正下限，量级远低于任何真实梯度。验证：该场景跑通，
**6,420 次 hook 调用中零个零 L1 行**。

任何改写逐样本梯度的防御都必须保证输出不产生零梯度，否则会被攻击实现的健全性检查
直接拒绝——**机制正确但整个 40 场景提交报废**。

## 隐私维度的天花板（重要结论）

把"补全攻击达到的 LRA"与"B 方特征上的**全监督**线性探针精度"对比：

| 数据集 | 基线 LRA | 全监督探针 | 128 标签探针 | 攻击超出全监督上界？ |
|---|---:|---:|---:|---|
| dataset_01 | 0.6289 | 0.5617 | 0.4992 | **是** |
| dataset_02 | 0.9256 | 0.9527 | 0.8761 | 否 |
| dataset_03 | 0.6465 | 0.7080 | 0.6881 | 否 |
| dataset_04 | 0.7069 | 0.8092 | 0.7045 | 否 |
| dataset_05 | 0.7579 | 0.9621 | 0.8262 | 否 |

**含义**：只有 dataset_01 的攻击真正用到了"无标签结构"（半监督优势），其余数据集的
LRA 都被 **B 方特征的线性可分性**卡住——那是数据自身的性质，A 方**无法改变**
（例如 dataset_02，被动方特征单独就把标签分到 0.95）。而 dataset_01 恰恰是本防御
LRA 表现最好的数据集（0.63，全场最低）。

因此**隐私得分主要由数据集决定，A 方可争取的空间很小**（本防御相对基线仅改善 0.0093）。
要在隐私上取得大幅提升，只能靠"让被动方表征变粗糙"这类会同时损害主任务的做法，
`configs/defense_purified_privacy.yaml`（满强度梯度重指派，LRA 压到随机水平）即属此类，
代价约 1.8 个精度点，且已在早期被判定为不划算。

### v6 失败的机制解释：抖动必须是"逐场景常量"，不能是"逐 batch 变量"

把三次 dataset_02 崩溃放在一起看，规律很清楚：

| 配置 | dataset_02/lfba_p20 精度 | 抖动在 dataset_02 上的行为 |
|---|---:|---|
| v3（已评分 37.96） | **0.9540** | 恒定开启（每个 batch 都抖） |
| 抖动全关（grid 实测） | **0.9609** | 恒定关闭 |
| v5（梯度重指派 0.3） | 0.5110（塌） | 恒定开启另加重指派 |
| v6（`jitterAnomalyGate: 2.5`） | **0.5431（塌）** | **按 batch 变化**（位移够才抖） |
| 无条件共模消除（第 9.11 节） | 0.5110（塌） | 训练期恒定，推理期全削 |

关键一行是 v6：**它是唯一让抖动在训练过程中"时开时关"的配置，而它和两个恒定配置
（v5 的重指派、无条件消除）一样塌了，却和两个"恒定开启/关闭"的配置表现相反。**

这说明 dataset_02 的主任务对**表征统计量的稳定性**敏感，而不只是对"抖动强度"敏感：
同一个场景内若一部分 batch 被抖动、另一部分不被抖动，被动方嵌入的分布会在 batch 之间
漂移，顶模无法稳定拟合，训练直接崩到随机水平。**因此门控应按"场景/数据集常量"来做，
而不是按 batch 的瞬时信号来做**——后者的代价在这个数据集上远超收益。

**据此排除的方向**：任何"逐 batch 自适应"的表征扰动（抖动门控、按 batch 的削幅、
逐 batch 的噪声强度）在 dataset_02 上都有同等风险，不再尝试。

## 第 19 轮：中位数批定位、测试时集成（均否决）

### 中位数批定位（`batchLocationStatistic: median`）

**想法**：LFBA 只替换它选中的那部分样本的表征，因此用**逐坐标中位数**做批定位理应比
均值更抗污染——均值会被污染的少数派拖走。

**实测（100 epoch，本地验证口径）**：

| 场景 | 均值（v3） | 中位数 |
|---|---|---|
| dataset_01_lfba_p20 | **0.6625 / ASR 0.7983** | 0.5667 / ASR 0.9833 |
| dataset_03_lfba_p20 | 0.9250 / **ASR 0.0990** | 0.9322 / ASR 0.2549 |
| dataset_02_lfba_p20 | **0.9540 / ASR 0.9967** | **0.5110 / ASR 1.0000（塌）** |
| dataset_02_clean | **0.9714** | 0.9699 |

**全面变差，且 dataset_02 再次精确塌到 0.5110。** 原因是训练与推理的**统计量不一致**：
`referenceMean` 始终按均值累积，推理改用中位数去与它比较，偏差本身即系统性偏移；叠加
训练期抖动让批分布更宽，偏离被进一步放大。与第 16 轮结论一致：**改动的统计量必须对训练
与推理完全一致**，任何"训练用一种、推理用另一种"的写法都会在 dataset_02 上崩溃。

### 测试时集成（未实施，说明原因）

**想法**：在推理侧对嵌入做随机扰动并聚合，平滑顶模的锐利决策边界，从而削弱触发器的
锐利效应。与训练期抖动不同，它不改变学到的表征，因此理论上不会破坏 dataset_02 的训练。

**未实施的原因**：`inferenceRepresentationHook` 在 `core/evaluator.py` 中**按 batch 调用**，
且钩子内部**拿不到顶模**——只能改写嵌入，不能聚合 logits。因此做不出真正的 randomized
smoothing（需多次前向并平均 logits），只能做"多噪声样本的嵌入聚合"，而均值聚合对零均值
噪声近似恒等，预期收益极低，却要改动真实推理路径，风险不成比例。**若允许修改推理循环，
这仍是值得一测的方向**（logits 级平滑有可证明的鲁棒性保证）。

### 评分结构（来自仓库根 `README.md`，原文）

> 自动评分由**性能、隐私和鲁棒性三部分组成，每部分 20 分**。自动评测 JSON 不包含工程分；
> 工程分及其他赛制分项由组织方另行评定。

**自动部分满分 60**，当前最好成绩 37.9599 ≈ **63%**，距 50 分（≈83%）差约 12 分。结合
第 13 轮的两个分数点（`balanced` 比 `precision` 低 1.2 分）可判断：**得分对主任务精度损失
极为敏感**，而精度正是 A 方最难改动的维度（基座模型结构不允许替换）。

### 为什么"性能"维度几乎没有提升空间

`configs/dataset_01.yaml` 给出关键结构事实：**`bottomType: resnet18`、`embeddingDim: 64`**。
被动方必须把 12288 维图像压到 **64** 维，同时还必须保住标签信息——因为主任务需要它。
这正好解释了 §10.2 的实测（线性探针在 dataset_01 上仅 0.5617，而补全攻击达到 0.6289）：
**标签信息是被压缩过程结构性保留的，A 方无法在不损害主任务的前提下移除它**。A 方能改的
只有 B 端收到的 cut 梯度，而削弱梯度必然同时削弱联合任务本身。

### 三个维度各自的状态

| 维度 | 现状（本地可测部分） | 判断 |
|---|---|---|
| 性能 | 40 场景均值 0.8844（对自有基线 +0.0108，20/40 更优） | 结构锁定，接近上限 |
| 隐私 | LRA 0.7239（对基线 −0.0093） | **基本锁定** |
| 鲁棒性 | 本地验证集 ASR 0.2944（劣于基线 0.2364） | **唯一有空间，但本地不可测** |

隐私维度"上界"的依据见 §10.2：补全攻击达到的 LRA 与 B 方特征上**全监督**探针几乎相同
（dataset_05：0.7579 vs 0.9621），说明该维度得分主要由**数据本身的可分性**决定；任何进一步
压低 LRA 的手段（满强度梯度重指派、加噪）都会同时显著损害主任务，实测均不可取。

### 结论与下一步

要把 37.96 推向 50，**增量只能来自鲁棒性**，而鲁棒性的评分输入
`backdoor_predictions.csv` 使用**隐藏测试集 + 组织方私有标签**（本地只有 `VAL_*` 标签，
包内是 `TEST_*` 预测），**无法本地复现或验证**。因此：

- A 方 hook 可触及的机制空间已穷尽（累计否决约 15 个机制/参数组合，全部记录在案）；
- 继续在本地猜测鲁棒性方向，已被 v4/v5/v6 连续三次证明会因 dataset_02 崩溃而失败；
- **需要外部信息（三个子分或目标权重）才能继续有效推进**。

**维持 `precision_v2` 作为提交件。**

## 第 21 轮：按攻击类型门控的无条件共模消除

### 为什么这个门控在原理上是对的

`core/trainer.py` 的 hook context 携带**公开场景标签** `backdoor`（`lfba`/`villain`/`none`，
经第 398 行 `**self.scenarioContext` 注入），因此防御**可以按攻击类型分别处理**，且不涉及
任何 B 方私有信息。这一点关键，因为两种攻击的几何性质完全不同：

- **VILLAIN** 对**每个**样本的被动方嵌入叠加**同一个固定触发向量**，因此
  **batch 均值偏移就是攻击本身**——无条件削掉它等于精确抵消。实测无条件共模消除可把
  dataset_02 的 VILLAIN ASR 从 0.3479 压到 **0.0039**。
- **LFBA** 替换的是它选中样本的**输入特征**，其破坏**不经过 batch 均值**。本轮新增的复合
  场景实测证实了这点：`dataset_02_composite` 的被触发批 **99.7%** 被判为异常
  （偏离/波动带中位数 **15.2**，干净批最大值仅 4.6），**但 ASR 仍为 0.98**——检测得再准也
  压不住，因为损害走的是逐样本通路。而无条件消除用在 LFBA 上，正是把 dataset_02 干净精度
  打到随机水平的那个操作。

因此"只对 VILLAIN 无条件消除"在机理上**分离了机制精确成立的情形与它摧毁任务的情形**。
实现为 `inferenceUnconditionalForAttacks: "villain"`（默认空串 = 不启用，**已提交配置行为不变**）。

### 实测（100 epoch，本地验证口径）

| 场景 | v3 | 门控 |
|---|---|---|
| dataset_01_villain | 0.6700 / ASR 0.4183 | **0.6975 / ASR 0.2717** |
| dataset_03_villain | **0.9629 / ASR 0.0694** | 0.9512 / ASR 0.0939 |
| dataset_05_villain | 0.9767 / 0.0070 | **0.9777** / ASR 0.0235 |
| **正式三项均值** | 0.8699 / 0.1649 | **0.8755 / 0.1297** |

注意：**`dataset_02` 与 `dataset_04` 的 VILLAIN 场景并不在正式 40 场景内**，那两个数据集
在正式赛制里只跑 LFBA/AMC（dataset_02）与 LFBA/VILLAIN/AMC（dataset_04，其 VILLAIN 是
官方场景之一）。上表只列正式启用 VILLAIN 的三个数据集。

### 结论：机理正确，但本地证据混合，暂不提交

三项均值上精度 **+0.0056**、ASR **−0.0352**，方向正确；但**逐场景不一致**：dataset_01 两项
都改善，dataset_03 两项都变差，dataset_05 精度升而 ASR 升。折算到 40 场景均值，精度增量约
**+0.0004**，落在噪声内。

考虑到四次失败都来自"小样本看着好、全量否掉"，且本地 ASR 与被评分 ASR 口径不同，
**不以 +0.0004 的本地预算冒一次全量提交的风险**。此项作为**已实现、机理已验证、待外部信息
确认**的候选保留——若平台子分显示鲁棒性偏低且 dataset_01 的 VILLAIN 是主因，改一个配置键
即可启用。

### 复合场景的触发可分性（补齐第 10.3 节地图）

`scripts/probe_recenter_signal.py`（60 epoch 探针）：

| 场景 | 干净批 中位数 / 最大 | 被触发批 中位数 / 最小 | 触发批被更正比例 | 本地 ASR |

## 第 23 轮：用平台分数反推评分模型——本地 ASR 代理不可用于决策

两个已评分版本是**同一套机制、只差一个参数**（异常判据阈值 3.0 vs 2.0），因此它们的
平台分差可当作一次受控实验来反推评分函数：

| 版本 | 本地验证集 ASR | 平台得分 |
|---|---:|---:|
| `precision`（阈值 3.0） | 0.2944（40 场景均值） | **37.9599** |
| `balanced`（阈值 2.0） | **0.0311**（⚠️ 仅 8/40 场景的部分快照） | 36.7445 |

> ⚠️ **数据可信度更正（第 24 轮）**：`balanced` 的 0.0311 来自一份**不完整快照**（当时只
> 抓到 8 个场景），**不是 40 场景均值**，且该快照与其缓存均已在清理中删除、**无法恢复**。
> 归档的 `outputs/final/comparison_table.md` 记录的是**已评分的 v3**，不含 `balanced`。
> 因此上表第二行只应作**方向性**参考。

**方向性矛盾**：在能比较的那部分场景上，`balanced` 的本地 ASR **明显更低**，而平台分
**更低 1.2154**。若 `balanced` 的 40 场景 ASR 均值实际与 `precision` 接近，那么分差就几乎
全部来自精度——这与"评分对精度损失敏感"的结论一致，也是本轮采取的保守解读。

无论取哪种解读，**操作性结论不变**：本地 ASR 无法解释这 1.2154 的分差，因此**不能用来
判断某个改动是否会提分**。这与第 16 轮已证的事实（包内是 `TEST_*` 预测、本地只有
`VAL_*` 标签，被评分的 ASR 无法本地重算）互相印证。

### 对后续决策的影响

| 决策 | 依据 | 可用性 |
|---|---|---|
| 是否该"压低 ASR" | 本地 ASR 代理 | **不可用**（无法解释已观测到的分差） |
| 是否该"保精度" | 平台分差（唯一真实反馈） | **唯一可用依据** |
| 是否该继续猜机制 | 无 | 已连续 4 次全量否决 |

因此后续**只保留"不损精度"的改动**，且其本地预算必须远超噪声才值得一次全量提交。
按此标准，第 21 轮"按攻击类型门控"（40 场景折算仅 +0.0004）**不提交**的判断得到进一步支持。

## 第 31 轮：逐样本标准化（否决）

**想法**：把表征对**冻结的训练统计量**做逐样本标准化 `x -> (x - mean) / scale`。这是
**逐样本映射**，因此整批共享的位移（正是 VILLAIN 的固定加性触发器）**在构造上被消掉**，
而样本之间的相对差异被保留——与"削掉 batch 均值"不同，后者会把样本压到一起从而摧毁任务。

**实测（100 epoch，本地验证口径，v3 → 标准化）**：

| 场景 | v3 acc / ASR | 标准化 acc / ASR |
|---|---|---|
| dataset_02_clean | **0.9714** | 0.8585（−0.1129） |
| dataset_02_villain | **0.9528** / 0.0862 | 0.9229 / 0.1481 |
| dataset_03_villain | 0.9629 / 0.0694 | 0.9611 / **0.0551** |
| dataset_01_villain | 0.6700 / 0.4183 | **0.7017** / 0.4200 |
| dataset_03_lfba_p20 | 0.9250 / 0.0990 | **崩溃** |

**两条否决理由**：

1. **会让攻击直接失败**：`dataset_03_lfba_p20` 抛
   `ValueError: LFBA cannot calculate L1 similarity from zero gradients`。原因是训练期除以的
   `referenceMeanStd` 是**逐坐标"批均值波动"的 EMA**，并不是该坐标的尺度；用错尺度做标准化
   会让表征数值严重偏离，反向传播的逐样本梯度塌成零，而 LFBA 的 L1 相似度构造拒绝零梯度。
   **攻击实现不得修改**，所以这不是可接受的副作用，而是硬否决。
2. **精度代价过大**：dataset_02_clean **−0.1129**，净收益仅 dataset_03/01 的局部改善
   （dataset_02_villain 反而变差）。

### 关于"参考统计量"的累计结论

至此，尝试过用它做异常判据（第 7/10 轮）、做稳健参考（第 11 轮）、做逐样本标准化（第 31 轮），
三次都失败，原因同一个：**`referenceMean` 与 `referenceMeanStd` 是为"批均值异常检测"这一
用途设计的量，不是逐坐标的分布统计量**。把它们挪作他用（阈值、标准化尺度）都会引入系统性
偏差，并在 dataset_02 或 LFBA 上以崩溃形式暴露。**这是本防御框架的边界，不是可调参数。**

## 第 32 轮：嵌入量化 / 特征压缩（否决）——并归纳出一条更普遍的约束

**想法**：把被动方嵌入逐坐标吸附到网格上，网格间距 = `quantizeStep × 冻结训练尺度`。
**小于一个网格间距的扰动无法把一个值挪到另一个格子里，因此会被"擦除"而不是像阈值法那样
只是被削弱**——这正好针对"触发器被底模压缩进干净波动带"的那些数据集。

**实测（100 epoch，本地验证口径）**：

| 场景 | v3 acc / ASR | quantizeStep=0.5 |
|---|---|---|
| dataset_02_clean | **0.9714** | 0.8881（−0.0833） |
| dataset_03_villain | 0.9629 / 0.0694 | 0.9638 / **0.0673** |
| dataset_01_villain | 0.6700 / 0.4183 | 0.6867 / 0.4483 |
| dataset_02_villain | 0.9528 / 0.0862 | **崩溃**（VILLAIN 找不到满足 `minimumMainTaskAccuracy` 的检查点） |
| dataset_03_lfba_p20 | 0.9250 / 0.0990 | **崩溃**（`LFBA ... zero gradients`） |

**否决**：净收益近乎为零（唯一改善是 dataset_03_villain 的 0.0673 vs 0.0694），代价是
dataset_02_clean **−0.0833**，并且**同时让两种攻击的官方实现失败**。

### 归纳：训练期改动必须保持可微结构，而不只是"改数值"

第 31、32 轮连续两个机制（逐样本标准化、嵌入量化）都是**通过"破坏攻击所依赖的计算"来失败的**：

| 机制 | 失败形式 | 直接原因 |
|---|---|---|
| 逐样本标准化 | LFBA 抛 `zero gradients` | 用错尺度（`referenceMeanStd` 是批均值波动，不是坐标尺度）导致梯度塌零 |
| 嵌入量化 | LFBA 抛 `zero gradients`；VILLAIN 找不到合格检查点 | `round()` 导数为零，攻击拿不到梯度；同时主任务精度跌破 `minimumMainTaskAccuracy` |

即：**任何在训练期改写被动方表征的防御，都必须保持它所经过的整条链路可微、且主任务精度
不低于攻击自带的健全性阈值；否则攻击不是被"削弱"，而是直接失败——那对赛题是无结果，
不是得分。** 这是一条比"不要破坏精度"更硬的约束，也是本项目 30 余个机制中最常见的
隐蔽否决原因。今后任何训练期机制在投入全量运行前，都应先在**LFBA 与 VILLAIN 两个场景**
上验证其可跑通（而不只是看精度）。

## 第 34 轮：按攻击类型门控抖动（候选 D，正在跑全量）

**想法**：抖动的收益是**攻击相关**的。第 18 轮已测出 dataset_02 的四个后门场景中抖动在三个上
完全无影响、一个只有精度代价；dataset_05 上关闭抖动为双赢；而 VILLAIN 上抖动有帮助。
既然 `backdoor` 标签对 hook 可见，就把抖动**限制在 VILLAIN 场景**——这等于**删掉一项已测出的
成本，而不引入新的变换**，因此应当优于第 31/32 轮被硬否决的那类"改写表征"。

**门控按场景标签判断，因此在单场景内是常量**（逐 batch 门控已被第 16 轮证伪）。

**试点（3 个 LFBA 场景）看起来是大胜**：dataset_02_lfba_p20 0.9540→0.9609、
dataset_05_lfba_p20 0.9087→**0.9602**、dataset_01_lfba_p10 0.6283→**0.6925**。

**但把全部 15 个 LFBA 场景测完，结论大幅收敛**：

| 指标（15 个 LFBA 场景） | 结果 |
|---|---|
| 精度 改善 / 变差 | **8 / 7** |
| 精度 均值变化 | **+0.0060** |
| ASR 改善 / 变差 | 9 / 5 |
| ASR 均值变化 | **+0.0245（变差）** |
| 折算到 40 场景均值 | **约 +0.0022（落在噪声内）** |

且 **clean 与 VILLAIN 场景逐字节相同**（实测 6 个场景完全一致），说明隔离干净——这正是
"只删成本、不动其它"应当有的样子。

> **又一次试点误导**：3 场景试点显示 +0.003～+0.057 的精度增益，全量 15 场景只有 +0.0060
> 均值且 7/15 变差。这是本项目第 5 次出现"小样本看着好、大样本收敛"（前四次：验证集 ASR、
> v5、v6、v3 vs balanced 的 ASR 对比）。**结论：任何变体在提交前必须测满全部同质场景
> （这里是全部 15 个 LFBA），3～5 个场景的试点只能用于排除崩溃，不能用于判断收益。**

全量 40 场景正在跑（`scripts/run_variant_snapshot.py --variant jitter_villain`），
完成后按 +0.0022 的预期判断是否值得作为第 4 个提交包。第 31、32 轮连续两个机制（逐样本标准化、嵌入量化）都是**通过"破坏攻击所依赖的计算"来失败的**：

| 机制 | 失败形式 | 直接原因 |
|---|---|---|
| 逐样本标准化 | LFBA 抛 `zero gradients` | 用错尺度（`referenceMeanStd` 是批均值波动，不是坐标尺度）导致梯度塌零 |
| 嵌入量化 | LFBA 抛 `zero gradients`；VILLAIN 找不到合格检查点 | `round()` 的导数为零，攻击拿不到梯度；同时主任务精度跌破 `minimumMainTaskAccuracy` |

即：**任何在训练期改写被动方表征的防御，都必须保持它所经过的整条链路可微、且主任务精度
不低于攻击自带的健全性阈值；否则攻击不是被"削弱"，而是直接失败——那对赛题是无结果，
不是得分。** 这是一条比"不要破坏精度"更硬的约束，也是本项目 30 余个机制中最常见的
隐蔽否决原因。今后任何训练期机制在投入全量运行前，都应先在**LFBA 与 VILLAIN 两个场景**
上验证其可跑通（而不只是看精度）。

## 第 41 轮：按用户要求改做"从现有 SOTA 找方案并改进"——共享方向（robust PCA）检测

用户明确要求"从现有 SOTA 算法中找寻方案并改进"。因此回到
`docs/vfl_backdoor_sota_and_defenses.md`（22 条来源的后门 SOTA 调研），重新审视其中
**唯一一条被标注为"公开 VFL 防御文献中未见实现"** 的机制（该报告第 4 节末尾）：

> 由于两种攻击都用**固定触发器**，对残差场做**共享方向检验**（robust PCA / 首位奇异向量）
> 是专用于固定触发器的检测器——在公开的 VFL 防御中未见实现。

本报告此前的实测支持这条思路：VILLAIN 触发造成的位移在首位奇异方向上能量占比 **1.0000**，
而 **LFBA 也有 0.6391**——即 LFBA 的位移**大部分是共模的**；而"共模消除"（本防御现有主力
机制）只带走 batch **均值**成分，抓不到这部分。因此这是针对 LFBA 的一个**新机制**。

**实现**（`defense/purified_vfl.py`，参数 `sharedDirectionStrength` /
`sharedDirectionThreshold`，默认 0 = 关闭）：对 batch 的中心化矩阵 R 做 SVD，计算首位
奇异方向的能量占比 `e = s1²/Σsi²`；当 `e > threshold` 时把样本投影到首位右奇异向量的
正交补，即扣掉该共享成分。**训练与推理使用同一统计量**，避免此前"训练用一种、推理用另一种"
造成的塌陷。

**实测（100 epoch，本地验证口径）**：

| 场景 | v3 | 强度 1.0 / 阈值 0.5 | 强度 0.5 / 阈值 0.5 |
|---|---|---|---|
| dataset_02_clean | 0.9714 | 0.9707 | 0.9678 |
| dataset_03_clean | 0.9801 | 0.9801 | 0.9729 |
| **dataset_02_lfba_p20** | 0.9540 / 0.9967 | **0.5110 / 1.0000（塌）** | 0.9588 / 1.0000（ASR 满） |
| dataset_03_lfba_p20 | 0.9250 / 0.0990 | 0.9295 / 0.1494 | 0.9421 / 0.0942 |
| **dataset_02_villain** | **0.9528** / 0.0862 | 0.9659 / 0.0550 | **0.7529 / 0.4875（崩）** |
| dataset_03_villain | 0.9629 / 0.0694 | 0.9638 / 0.0612 | 0.9611 / 0.0714 |
| dataset_01_villain | 0.6700 / **0.4183** | 0.6700 / 0.4800 | 0.6508 / **0.5367** |

**否决**。半强度下**所有攻击场景都变差**（dataset_02_villain 精度 −0.200、ASR 0.0862→0.4875；
dataset_01_villain 精度 −0.019 且 ASR 0.4183→0.5367）；全强度下 dataset_02_lfba
**第 5 次精确塌到 0.5110**。

### 为什么这个机制在 VFL 里必然失败（重要结论）

文献中的共享方向 / robust-PCA 检测源自**拆分学习（split learning）**：那里的 embedding 由
**单个**客户端从原始数据学出，干净批次的残差近似各向同性，共享方向 ≈ 触发器方向。

但本赛题是 **VFL**：B 方 embedding 承载的正是**标签信息**，而同一 batch 内样本的类别结构
本身就是一个强共享方向。**干净 batch 的首位奇异方向就是类均值方向**，而不是噪声。因此：

> **在 VFL 中，"共享方向"与"类别结构"不是两个可分的量，它们在定义上就是同一个东西。**
> 按共享方向投影，等于在删类别信息——这解释了它为什么同时压低 VILLAIN 的精度，并把
> dataset_02 打到随机水平。

这与本文件第 5 节第 1 条（ProtoGuard-SL 的跨类近邻规则在真实数据上失效）是**同一类错误的
第二次实例**：文献里这两类方法的有效性都预设了"embedding 不含类别结构"，而这正是 VFL 与
SL 的根本差别。**该报告第 4 节这条"未见实现"的建议，现已被本项目实测证伪。**

### 对"从 SOTA 找方案"这条路的结论

`docs/vfl_backdoor_sota_and_defenses.md` 已系统性评估 11 种 VFL 专用防御（D1–D11）与 9 种
经典防御。逐条对照"只用 A 方合法可见信息"这一约束后：

| 类别 | 代表 | 在本赛题的可移植性 |
|---|---|---|
| 需要 ≥3 参与方 | VFLIP、VFLMonitor、Krum、Trimmed-mean、FLAME、SafeSplit | **结构性退化**（两方下"多数投票"无意义） |
| 依赖类别结构 | ProtoGuard-SL、SCAn、共享方向/robust PCA | **已被实测证伪**（第 5 节第 1 条 + 本轮） |
| 改客户端训练目标 | 互信息正则化、VIB | **超出 A 方 hook 边界** |
| 改模型参数 | Fine-Pruning | **规则禁止**（不得替换基座模型） |
| 需要访问顶模 logits | CONFIRM、STRIP | **hook 拿不到顶模**，只能改 embedding |
| 诱饵批次检测 | SplitGuard | 需在 A 的训练循环注入诱饵并观测返回梯度——**理论上可移植，尚未实现** |

即：现有 SOTA 中能落进"只用 A 方合法可见信息"约束的条目，**要么已在本项目中被测过并否决，
要么需要 ≥3 方、改协议、改模型或访问顶模**。这是本轮最有价值的产出——把"这条路是否还有矿"
从猜测变成了逐条排除的结论。

唯一仍未被尝试、且**不越界**的条目是 **SplitGuard 式的诱饵批次检测**（A 在自己的训练循环里
注入已知行为的诱饵样本，检查返回的 cut 梯度是否符合预期）。它针对的是"B 是否在训练中做了
手脚"，理论上契合现有 hook；但其公开评估只针对**训练劫持**，对本赛题的**推理期固定触发器**
（VILLAIN/LFBA 都在测试时注入）是否有效**未经任何验证**。

## 第 42 轮：联网检索 SOTA 并落地 SecureSplit（WWW 2026）——结构性否决

按用户要求，联网检索现有 SOTA 并动手实现。检索到的关键工作与其可移植性：

| 工作 | 出处 | 核心机制 | 本赛题适配 |
|---|---|---|---|
| [VFLIP](https://ar5iv.labs.arxiv.org/html/2408.15591) | ESORICS 2024 | MAE 重构误差 + 参与方多数投票 → 净化 | 两方下**多数投票退化**（调研已记录） |
| [SecureSplit](https://ar5iv.labs.arxiv.org/html/2601.14054) | **WWW 2026** | UMAP 降维 + 多项式核升维 → 自适应多数半径滤波 | **本轮实测否决（见下）** |
| [ProtoGuard-SL](https://arxiv.org/pdf/2604.03595) | ICME 2026 | 类原型 + 共形 p 值 | 第 5 节已实测否决 |
| [FILTER](https://www.scilit.com/publications/7b58d7f700d0ddb684408a9407be02b1) | AAAI 2026 | 训练后段双过滤器剔除投毒样本 | 数字未核验 |
| [SafeSplit](https://www.ndss-symposium.org/wp-content/uploads/2025-1698-paper.pdf) | NDSS 2025 | DCT/旋转距离 + 回滚 | 需 ≥3 方 U 型顺序，协议不让改 |

### SecureSplit 的精确算法（已从全文核验，非摘要）

来自 arXiv:2601.14054 的 Algorithm 1 与式 (5)–(8)：

```
Λ      = Median(H_1..H_m)                                     (5) 逐坐标中位数
R      = min{R' : #{k : ||H_k - Λ||₂ ≤ R'} ≥ m/2}             (6) 覆盖至少一半的最小半径
R_adp  = (1 + 1/(α + σ)) · R                                  (7) 按方差自适应
良性   ⟺  ||H_k - Λ||₂ ≤ R_adp                               (8)
```

**它为什么看起来适配**：该算法面向**拆分学习中服务端**的角色——正是 A 在本赛题的位置；
且它预设"只有少数 embedding 被投毒"。而 VILLAIN **确实只污染一部分**：
`attacks/backdoor/villain.py::selectPoisonIds` 只从 `knownTargetIds` 里按 `poisonRate`
抽 `poisonRate × |knownTargetIds|` 个目标类样本。前提成立。

**实现**（`defense/purified_vfl.py::_secureSplitFilter`，参数 `secureSplitStrength` /
`secureSplitAlpha` / `secureSplitLinkOnly`）：逐坐标中位数 → 式(6) 半径 → 式(7) 自适应
半径 → 式(8) 判定；被标记样本**朝 Λ 修复**（而非论文的"剔除"，因为 hook 不能丢样本，
且 BVBench 明确指出"修复优于剔除"）。`secureSplitLinkOnly` 可选启用论文 Step I 的
多项式核升维；UMAP 未实现——它需要在整个 split 上做随机拟合，per-batch hook 内不可用。

### 实测（100 epoch，本地验证口径）

| 场景 | v3 | SS 强度1.0 / α1.0 |
|---|---|---|
| dataset_02_clean | 0.9714 | **0.8865（−0.0849）** |
| dataset_04_clean | 0.8552 | 0.8385（−0.0167） |
| dataset_01_villain | 0.6700 / ASR **0.4183** | 0.6675 / ASR **0.5250（双差）** |
| dataset_02_lfba_p20 | 0.9540 / 0.9967 | **崩溃** |
| dataset_02_villain | 0.9528 / 0.0862 | **崩溃** |
| dataset_03_lfba_p20 | 0.9250 / 0.0990 | **崩溃** |
| dataset_03_villain | 0.9629 / 0.0694 | **崩溃** |

崩溃形式正是第 32 轮总结的两条硬否决：

- LFBA → `ValueError: LFBA cannot calculate L1 similarity from zero gradients`
- VILLAIN → `RuntimeError: VILLAIN did not produce a checkpoint meeting minimumMainTaskAccuracy`

### 为什么它在本赛题必然失败（第三个同类实例）

**SecureSplit 的"多数"是"按样本的多数"，而它成立的前提是 embedding 空间中不存在类别结构。**

在 SL（论文的设定）中服务端拿到的是**同一批样本、由多个客户端切分**的 embedding，逐样本
的分布近似同质，因此"距离逐坐标中位数太远的少数样本 = 被投毒"是合理判据。

但本赛题是 **VFL**：B 方 embedding 承载的正是**标签信息**，同一 batch 内不同类样本天生就
相距很远。于是式(6) 的"覆盖一半的最小半径"和式(8) 的判决**会把一整个类的正常样本判为异常**
并朝中位数拉平——这正是干净精度掉 0.085、且攻击因精度/梯度退化而直接失败的原因。

这与第 5 节第 1 条（ProtoGuard-SL 跨类近邻规则失效）、第 41 轮（共享方向/robust PCA 失效）
构成**同一根因的三次独立实例**：

> **凡是把"偏离多数中心"当作投毒证据的方法，其有效性都预设了 embedding 不含类别结构。
> 这在 SL/FL 中大致成立，在 VFL 中不成立——因为在 VFL 里"类别结构"与"异常"在定义上是
> 同一个东西。**
>
> 由此得到一条可判定的筛选规则：**任何 SOTA 防御，若其判据是"样本相对批中心/多数的偏离"，
> 在本赛题上可直接预测失败，无需实现。**

### 对"从 SOTA 找方案"这条路的最终结论

把调研到的 20 条防御逐条对照"只用 A 方合法可见信息"这一约束后：

| 类别 | 代表 | 结论 |
|---|---|---|
| 判据 = 相对批中心/多数的偏离 | ProtoGuard-SL、SecureSplit、共享方向/robust PCA、Trimmed-mean、median | **结构性失败（三次实测）** |
| 需要 ≥3 参与方 | VFLIP、VFLMonitor、Krum、FLAME、SafeSplit | 两方下退化 |
| 改客户端训练目标 | 互信息正则化、VIB | 超出 A 方 hook |
| 改模型参数 | Fine-Pruning | 规则禁止 |
| 需要顶模 logits | CONFIRM、STRIP | hook 拿不到顶模 |
| 训练期诱饵批次 | SplitGuard | 未验证，且两种攻击都在**测试时**注入 |

因此**现有 SOTA 中不存在可直接移植、且能在本赛题约束下成立的方案**——这不是"还没找到"，
而是逐条排除后的结论。

### 目前唯一有效的方向仍是逐样本修正（第 41 轮候选 A / B）

在 40 余轮中，唯一在**关键场景上同时改善精度与 ASR** 的机制是"逐样本超额裁剪"：
dataset_02_lfba_p20 精度 0.9540 → **0.9696**、本地 ASR 0.9967 → **0.5316**（腰斩）。
它与上述所有被否决机制的区别恰在于：**不依赖"偏离多数 = 异常"**，而是逐样本沿共享方向
裁掉超额部分、并保留批中心。代价是它当前会在 `dataset_04/clean` 上训练发散
（`cutGradientHook output produced non-finite values`），这是**实现稳定性问题，不是机制缺陷**，
仍是后续最值得投入的修复对象。

### 决定性差异：A 内在不稳定，B 不崩

候选 A 在 **`dataset_04/clean` 上使训练发散到 NaN**，场景直接中止（
`cutGradientHook output produced non-finite values`）。用漂移轨迹探针实测：

| 配置 | dataset_04/clean 表征 |max| 轨迹 |
|---|---|
| A 原始 | epoch0 0.2479 → epoch11 **5.76**（23 倍） |
| A + 两次数值加固后 | epoch0 0.2479 → epoch15 **15.57**（63 倍），**增长更快** |

两次数值加固（把修正量上限压到本批带宽、把发散防护从"平均范数"改为"最大范数"）**不但没
止住，反而加速了增长**。这证明它是**机制内在的不稳定**而不是数值问题：

> A 从 B 的**批级**表征里删掉一个由本批样本共同决定的方向，顶模必须去补偿这个被删掉的
> 结构，补偿又改变下一批的梯度，形成正反馈。**任何依赖批级统计量去改写 B 的表征的机制，
> 都会被这个正反馈放大。** 这与第 16 轮（逐 batch 抖动门控使 dataset_02 崩溃）是同一条
> 规律的两个实例。

候选 B **只用单样本统计量**（不计算 batch 的均值/中位数/SVD 或任何其它样本的函数），
每个样本独立判定与修正，因此没有这个正反馈通道，**从不崩溃**。

| factor | d02_lfba_p20 | 判定 |
|---|---|---|
| 2.0 | acc 0.5110 / ASR 1.0000 | **过紧**：把正常样本也压了，主任务塌到随机水平 |
| **2.5** | **acc 0.9678 / ASR 0.4914** | **最优点** |
| 3.0 | acc 0.9675 / ASR 0.9957 | **过松**：ASR 基本未动 |

### 选型结论

**采用候选 B（`normExcessStrength: 1.0`、`normExcessFactor: 2.5`）**，理由按权重排序：

1. **它不崩**。A 会让 `dataset_04/clean` 中止，而**场景中止等于无结果**——这是硬约束
   （第 32 轮规则）。
2. **在最关键场景上 ASR 更低**：d02_lfba_p20 从 0.9967 降到 **0.4914**（A 是 0.5316），
   而该场景此前连续 6 次让所有机制塌陷或失效。
3. **在 d03_lfba_p20 与 d01_villain 上双赢**（精度与 ASR 同时改善）。
4. **它满足更严的审计口径**：只用单样本统计量，不依赖批内其它样本。

A 只在 d03_villain 的 ASR 上略优（0.0571 对 0.0673）、在 d02_clean 精度上略优
（0.9710 对 0.9701），这两项优势远不足以抵消"会崩"。

（配置 `configs/defense_purified_norm_excess.yaml`）。

## 第 44 轮：拿到官方评分公式，据此重新定向

用户提供了官方评分标准（和鲸平台赛题页）。三条公式与之前"每部分 20 分"的粗略描述相比，
**结构完全不同**，且直接改变了优化方向。

### 官方公式（原文）

**1. 模型性能（20 分）** —— 归一化效用，干净场景不计入平均

```
U       = clip((A - A_min) / (A_clean - A_min))      # clip 到 [0,1]
S_perf  = 20 × mean(U)
```

- `A_clean` = 官方无攻击、无防御的干净基线精度；`A_min` = 随机猜测（二分类 0.5，
  dataset_05 六分类 1/6≈0.1667）。
- **干净场景本身不计入平均**，只用于提供 `A_clean`。
- **LFBA 的三个投毒强度 p=[0.05,0.1,0.2] 先在 LFBA 族内平均**，因此 LFBA 每个数据集只算
  **一个**条目，而不是三个（避免 LFBA 获得三倍权重）。

**2. 隐私保护（20 分）** —— 归一化恢复率 × 精度约束

```
P    = clip((A_attack - A_recovered) / (A_attack - A_min))
G_p  = clip((A - A_min) / (0.9·A_clean - A_min))
Q_p  = G_p × P
S_priv = 20 × mean(Q_p)
```

`A_attack` = 无防御基线的标签恢复率，`A_recovered` = 防御后恢复率。**`G_p` 是精度约束因子**，
明文写着是为防止"显著降低模型性能来换取较低标签泄露"。

**3. 安全鲁棒性（20 分）** —— 精度约束与后门抵抗率的**调和平均**

```
G_r    = clip((A - A_min) / (0.9·A_clean - A_min))
R      = 1 - ASR
Q_r    = 2·G_r·R / (G_r + R)
S_sec  = 20 × mean(Q_r)
```

### 三条结构性结论（决定了后续该做什么）

**结论一：精度同时进入三项，且在隐私/鲁棒中作"约束因子"。**
`G_p` 与 `G_r` 都等于 `clip((A - A_min) / (0.9·A_clean - A_min))`。注意分母是
**0.9 × A_clean**：一旦实际精度达到干净基线的 90%，约束因子就饱和为 1；**低于它则线性衰减**。
因此精度既是性能分的直接输入，又是另外两项的乘数——**保精度是首要目标，这与两个已评分点
的经验完全一致**（`jitter_villain` 精度 +0.0022、本地 ASR 反而 +0.0199，平台分却涨 0.15）。

**结论二：鲁棒项用调和平均，因此 ASR 与精度互相"卡脖子"。**
`Q_r = 2·G_r·R/(G_r + R)`。调和平均意味着**任一项低都会把整项拉低**：即使 `R` 接近 1
（ASR≈0），若 `G_r` 只有 0.5，`Q_r` 也只有约 0.67。所以"靠牺牲精度换低 ASR"在这条公式下
**双重受罚**（`G_r` 下降 + 性能分下降）。这解释了为什么 `balanced`（大幅压 ASR、牺牲精度）
总分反而低 1.2。

**结论三：LFBA 三档先在族内平均，说明 LFBA 不是三倍权重的重点。**
真正决定性能分的是**每个数据集各贡献一个条目**（LFBA 合并后 + VILLAIN + PMC + AMC +
composite，共 5 条目/数据集 × 5 数据集 = 25 条目，与本地 `n(性能)=25` 吻合）。
因此**提升最差的数据集（dataset_01，干净基线仅 0.7308）的收益远大于在 dataset_05 上刷分**。

2. **性能项（18.9/20）**：靠提升最差数据集（dataset_01，干净基线 0.7308）。
3. **鲁棒项（约 15/20）**：只能用 hidden test 评估，本地不可优化，只能靠结构证据。

## 第 45 轮：隐私项攻关成功——梯度重指派按场景门控

### 动机来自官方公式

用户提供的官方评分公式暴露了最大的得分缺口：

```
隐私：P = clip((A_attack - A_recovered) / (A_attack - A_min))
      G_p = clip((A - A_min) / (0.9·A_clean - A_min))
      Q_p = G_p × P,   S_priv = 20 × mean(Q_p)
```

本地实测 `A_recovered = 0.7239` 与无防御的 `A_attack = 0.7332` **几乎相等**，因此
`P ≈ 0.05`，**隐私项 20 分只拿到约 4.9 分**。对比：性能项约 18.9/20、鲁棒项约 15.2/20
（且本地不可观测）。**隐私是三项里空间最大的一项，约 15 分。**

### 为什么此前失败、现在为什么能成

历史上唯一能把标签恢复率压到随机水平的机制是**满强度逐样本梯度重指派**
（`gradientShuffleStrength: 1.0`，dataset_03 实测恰好 0.5000）。它此前被否决，是因为
**用法错误**：当时是**全局**开启，于是在后门场景里也生效，使 VILLAIN 找不到满足
`minimumMainTaskAccuracy` 的检查点、**场景直接中止**（第 12、26 轮）。

但读 `core/experiment.py` 的分派逻辑可以发现一个结构性事实：

| `backdoor` 名 | 训练入口 | 受影响场景 |
|---|---|---|
| `none` | `trainer.train()`（基类循环） | **PMC / AMC / clean** |
| `lfba` | `runLfbaTraining()`（独立循环） | LFBA |
| `villain` | `runVillainTraining()`（独立循环） | VILLAIN |

**PMC/AMC 的标签推断攻击恰恰发生在梯度通路上**，而 LFBA/VILLAIN 有各自独立的训练循环。
因此把重指派限制到 `labelInference != none` 的场景，就能打击隐私泄露**而完全不碰后门训练**。

新参数：`gradientShuffleLabelInferenceOnly`（默认 `false`，不影响任何已交付配置）。

|---|---|---|
| dataset_03_pmc | 0.9801 / 0.5696 | 0.9575 / **0.4955**（随机水平） |

| **dataset_03_lfba_p20** | 0.9250 / ASR 0.0990 | **0.9250 / 0.0990（逐位不变）** |

**门控完全按设计工作**：两个后门场景**逐位不变**——这正是它不会像全局开启那样让 VILLAIN

### 预期收益（按官方公式估算）

LRA 均值从 0.7239 → 约 0.60（若 15 个标签推断场景均按此比例下降）。按

性能/约束因子损失（约 1~2 分），**净收益预计约 +4 分**。

这是自 38.11 分以来第一个有量级意义的改进方向。注意：本地验证集 ASR/LRA 与 hidden test

### 结论一：梯度噪声在隐私维度上**明确无效**（排除一整条路线）

> 若要继续提升必须换机制族（FIDP 的逐维度重要性加权是唯一剩下的候选）。

### 结论二：VFL-FIDP 的机制分析（`code/VFL-FIDP(VFLAIR)`）

读了源码。核心是 `VFL_FIDP_Defense`，三个组件：

1. **`compute_gini_importance(local_features, encrypted_labels)`** —— 逐特征算
   `Gini = 1 − 类内方差/总方差`。类内方差越小、类间差异越大，该维度越能泄露标签。
2. **`allocate_feature_budget` / `map_budget_to_embedding`** —— 按重要性**反比**分配隐私
   预算，再经卷积权重 `A_jk = (1/hw)·Σ|W_kj|` 把特征级预算映射到嵌入维度。
3. **`calculate_zcdp_noise` / `inject_noise`** —— 按维度注入对应强度的高斯噪声。

**与本赛题的适配性分析**：

- 它设计给**被动方**（`local_features` 是被动方的原始特征），但本赛题 A 方**不得使用 B 的
  特征**——所以必须改成在 A 的表征上计算重要性。这是可做的，因为 A 持有标签。
- 组件 2/3（按维度加噪）与结论一冲突：**加噪在本赛题无效**。
- **唯一没被本仓库试过的是组件 1**：用 A 的标签算**逐维度**标签重要性。第 31 轮的
  "逐样本标准化"失败是因为用了 `referenceMeanStd`（批均值波动的 EMA），**不是真正的
  逐维度重要性统计量**。FIDP 给的 `Gini = 1 − 类内方差/总方差` 才是正确的量。

因此本轮把 FIDP 实现为 `_embeddingImportance` + `_addImportanceWeightedNoise`：

- 用 A 的标签算逐维度 Gini 重要性；
- 归一化为均值 1 的噪声权重 `0.5 + importance`（重要性越高、噪声越大），并用动量平滑；
- 作用在**表征**上（而非被 Adam 吸收的梯度缩放），且门控到纯标签推断场景。

**统计量单元验证**：构造一个"标签揭示维度"（类间差异大、类内噪声小）和一个纯噪声维度，
`_embeddingImportance` 给出的权重为 **`[1.181, 0.455, …]`** —— 标签揭示维度获得 1.18× 的
平均噪声，纯噪声维度只有 0.46×，判定方向正确。

参数：`embeddingImportanceNoise`（默认 0.0）、`embeddingImportanceMomentum`（默认 0.9）、
`embeddingImportanceLabelInferenceOnly`（默认 false）。**默认全部关闭，不影响任何已交付配置。**

K 相对 H 的本地公式预测是 **+0.48**（k 的隐私项本地算 8.690 对 h 的 8.848 其实已更低，
差异主要来自性能项），但**平台实测 −0.99**。

把三次"加噪/表征改写"类改动在平台上的表现放在一起：

| 机制 | 本地验证表现 | 平台实测 |
|---|---|---|
| 统一梯度加噪（历史） | LRA 几乎不动（0.6772→0.6763） | 无收益 |
| `norm_excess`（候选 F/G） | d02_lfba 局部大幅改善 | 公式反降，未提交 |
| **FIDP 选择式应用（候选 K）** | 隐私项本地最高 | **−0.99** |

> **规律：以"注入噪声 / 改写表征分布"为核心、且收益依赖本地验证集的改动，
> 在隐藏测试集上收益不复现，甚至倒亏。** 这与"逐样本重指派"（平台 **+3.52**）
> 形成鲜明对照——后者破坏的是**攻击可利用的结构**（样本↔梯度对应关系），
> 而非依赖某个本地统计量。
>
> **可判定推论：后续应优先选择"结构性破坏攻击可利用信息"的机制，
> 而不是"注入噪声以稀释信息"的机制。**

"结构性"机制。已知在平台上确实有效的一类只有逐样本/逐维度的**结构性改写**
（重指派已用尽，`gradientShuffleStrength` 已达上限 1.0）。

**结论：在没有新的结构性机制之前，不应再提交基于加噪的变体。**

**M−H ≈ +0.19**——约为标定模型绝对误差均值（0.187）的 1 倍，**不足以支撑提交决策**。

### 二、必须纠正的一个语义误解

我原本以为 `gradientShufflePoisoningBackdoors: ["lfba"]` 的意思是"**排除** LFBA"。
**实际语义是"允许 LFBA 进入 poisoningActive 分支"**：

```
poisoningBranch = poisoningActive and backdoor in {"lfba"}
```

对 LFBA 攻击批：`backdoor="lfba"` 在集合里且 `poisoningActive=True` → **分支开启**。

所以候选 M 的真实形态是：

> **在 LFBA 攻击批 + 复合攻击批开启重指派，同时移除了纯标签推断场景的重指派**
> （因为它把 `gradientShuffleLabelInferenceOnly` 设成了 false）

这解释了 M 的三项变化：鲁棒 +1.418（LFBA 攻击批的 ASR 普遍下降）、
性能 −0.344 与隐私 −0.766（纯 LI 场景失去了 H 的隐私收益）。

**VILLAIN 必须排除**这一点是实测要求：它的 `poisoningActive` 覆盖整个攻击阶段，
在那里开启会让它达不到 `minimumMainTaskAccuracy` 而中止场景（候选 L 第一次运行即如此）。
D 的 `["lfba"]` 白名单正确实现了这个排除。

### 三、关键发现：H 与 M 的作用域**完全互补**

逐场景核对 H 与 M：

| | 数量 |
|---|---|
| 逐位相同的场景 | **22 / 40**（clean、villain、pmc、amc 全部相同） |
| 不同的场景 | **18 / 40**（lfba_p05/p10/p20 各 5 个 + composite 3 个） |

即：

- **H 只在纯标签推断场景（pmc/amc）与 clean 上有所不同**（它启用了纯 LI 分支）
- **M 只在 LFBA 与复合场景上有所不同**（它启用了 LFBA 攻击批分支）
- **两者没有任何重叠的场景**

而它们的收益恰好落在**不同的评分维度**上：

| | 纯 LI 分支（H） | LFBA 攻击批分支（M） |
|---|---|---|
| 作用的场景 | pmc / amc | lfba / composite |
| 压低的是什么 | 标签恢复率 | 后门 ASR |
| 提升的评分项 | **隐私项**（8.848） | **鲁棒项**（17.114） |

### 四、候选 N：两者叠加

因为作用域不重叠、收益维度不同，**两者应当可以直接叠加**：

`configs/defense_purified_n.yaml` = H + M 的两条分支同时开启

```yaml
gradientShuffleLabelInferenceOnly: true       # H 的纯 LI 分支
gradientShufflePoisoningActiveOnly: true      # 加上 M 的 LFBA 攻击批分支
gradientShufflePoisoningBackdoors: ["lfba"]
```

**预测**（按作用域不重叠的推论）：

| 项 | H | M | **N（预测）** |
|---|---|---|---|
| 性能 | **17.864** | 17.520 | 17.864 |
| 隐私 | **8.848** | 8.082 | 8.848 |
| 鲁棒 | 15.696 | **17.114** | **17.114** |
| 公式总分 | 42.409 | 42.715 | **≈ 43.826** |

即 N 应当**同时取得 H 的性能+隐私与 M 的鲁棒**，公式总分约 **43.83**，
按标定模型预估平台分约 **42.3**（较 H 的 41.6341 提升约 **+0.66**）。

这是本项目第一次出现"两个已验证的机制可以正交叠加"的情况——因为此前的机制
（加噪、FIDP、范数裁剪）都作用于同一通道而互相抵消，而这两个分支作用于**互斥的场景集**。

全量 40 场景运行中（`scripts/run_variant_snapshot.py --variant n`）。

### 二、更正：第 55 轮的推论错在哪里

我当时假设 H 与 M 的差异来自**两个不同的机制来源**（H 的纯 LI 分支 vs M 的 LFBA 分支），
因而可以正交叠加。**实测证伪**：

**H 与 M 在纯标签推断场景（pmc/amc）的 LRA 完全相同（10/10 逐位一致）。**
即**纯 LI 分支在 H 与 M 中都开启且效果相同**——它不是两者的差异所在。

H 与 M（以及 N）的**全部差异只有一件事**：

> **重指派是否在复合场景的后门攻击批开启**（H 关闭；M/N/L 开启）

而这一个改动同时带来三面效果：

| 维度 | 变化 | 具体来源 |
|---|---|---|
| 鲁棒 | **+1.418** | LFBA 攻击批的 ASR 普遍下降（`d02_lfba_p10` 的 Q_r +0.6633、`d01_lfba_p20` +0.3762、`d02_lfba_p05` +0.2171…） |
| 隐私 | **−0.766** | 复合场景的 LRA 变差（`d02_composite` 0.5110 → 0.9102） |
| 性能 | −0.344 | LFBA 攻击批的精度代价（`d02_lfba_p20` 0.9693 → 0.8516 等） |

**这三者是同一个改动的两面，不是可以分别取舍的独立机制。** 所以"取各维度最优的组合"
在这个改动上是不可行的——只能整体选择开或关。

## 第 57 轮：新机制检索的最终结论——防御地图已穷尽

按用户要求继续检索新机制。这一轮检索到 4 篇此前未覆盖的工作，以及一份权威综述，结果把
"防御空间"完整划清了。

### 一、权威综述给出的**可行性判据**（[arXiv:2402.03688](https://arxiv.org/abs/2402.03688)）

该综述（JACM，RPI/浙大/蚂蚁）明确列出每类 VFL 防御所需的**能力**：

> ① 需可信第三方　② **需控制训练过程**　③ 需参与方协调　④ 需专用安全硬件

**本赛题 A 方只有三个 tensor hook，这四条一条都不满足。** 而综述把加密类
（HE / MPC / 秘密共享 / TEE）**全部**归入需要这些能力的一类。这从权威分类上
独立确认了加密路线不可行——与我第 56 轮从"攻击不经过 A↔B 通道"得到的结论一致。

### 二、逐条可判定性（含本轮新检索到的 4 篇）

论文自己的对比表（CausShield TABLE I）列出代表方法及其前提，逐条对照本赛题约束：

| 方法 | 关键前提 | 本赛题判定 |
|---|---|---|
| **CoAE**（[2112.05409](https://arxiv.org/abs/2112.05409)，式 15 `ȳ=Enc(y;W_e)`、`ŷ=Dec(ȳ;W_d)`） | 黑盒假设：被动方不知主动方模型/数据 | **阻塞**：本赛题明确提供基座模型结构，该假设不成立；且需训练编解码器接入训练循环 |
| **CausShield**（2026, 因果表征） | ① 防御目标是**样本重建**而非标签推断；② 防御者是被动方；③ 被动方**无标签**（故用无监督代理数据集）；④ 在**传输前**重塑被动方表征 | **阻塞**：四项全部不符——我们要防标签推断、A 是主动方、A 持有标签、无被动方表征重塑通道 |
| InvL（USENIX Sec'25，自适应噪声） | Jacobian 谱校准的噪声注入 | **已被本赛题证伪**（加噪族，平台 −0.99~0） |
| InvL / Soteria / NoPeek / DISCO / ResSFL / Inf2Guard | 表征重塑 / 对抗训练 / 互信息最小化 | **阻塞**：均需改客户端训练目标或改底模参数，超出 A 方 hook |
| DMIAFP | 需真值标签 + 分类器联合训练净化模块 | **阻塞**：需改训练过程 |
| D3SFL | 需标注辅助集 + 完整模型梯度 | **阻塞**：超出 hook |
| PriFU | 需真值标签 + 端到端反传，且只保护推理阶段 | **阻塞**：超出 hook |
| LP-MST / Grafting-LDP / ID-LMID（VFLAIR） | 被动方侧隐私机制 | **方向相反**（本赛题 B 是攻击方） |
| VFLDefender（TIFS 2024） | 需控制训练过程 | **阻塞** |
| PRIVEE（2025，顺序保持置信扰动） | 面向**特征推断**，需改输出置信度 | **不对口**（我们防标签推断） |

### 三、本轮新增的实测证据：泄露通路确实已被我们打掉

用 `scripts/probe_gradient_sign_leak.py` 直接检验 CoAE 赖以成立的
**Lemma 1**（软max+交叉熵下，`∂ℓ/∂H` 的符号翻转指向真实类）：

```
场景: dataset_03_pmc,  防御: configs/defense_purified.yaml（无重指派）
hook 调用 11858 次, 检验 2560 行
cutGradient 行均值符号与标签的一致率 = 0.1926   （随机 = 0.5）
=> 梯度符号确实强烈泄露标签
```

**这条通路是真的**，而**我们的逐样本梯度重指派正是打掉它的手段**——它置换样本↔梯度的
对应关系，使符号不再指向该样本的标签。这也解释了 H 的隐私项为何能从 2.78 升到 8.85。

而 CoAE 只是想用"标签混淆"来破坏**同一条**符号结构，属于更弱、且前提不成立的手段。

### 四、最终结论：现有文献中已无可移植的新机制

把 13 个候选逐条判定后，结论是**防御地图已经穷尽**：

| 类别 | 代表 | 判定 |
|---|---|---|
| 加密 / MPC / TEE | HE、SS、Paillier、TEE | 需 TTP 或改协议；且攻击不经过 A↔B 通道 |
| 加噪 / 稀疏化 / 量化 | DP、RLAP/`dp_gc_ppdl`、`TensorPruner`、InvL | **本赛题实测证伪**（平台 −0.99~0） |
| 批中心/多数偏离判据 | SecureSplit、ProtoGuard-SL、共享方向 | **实测证伪**（VFL 中"类别结构"="异常"） |
| 标签混淆 / 软标签 | CoAE、LADistill | 黑盒假设不成立，或需改顶模目标 |
| 表征重塑 / 互信息 | DISCO、NoPeek、Inf2Guard、CausShield | 需改客户端训练目标或底模参数 |
| 需标签监督的净化 | DMIAFP、D3SFL、PriFU | 超出 A 方 hook |
| 需 ≥3 方 | VFLIP、VFLMonitor、Krum、FLAME、SafeSplit | 两方下退化 |
| 改模型参数 | Fine-Pruning | 规则禁止 |
| **结构性破坏逐样本对应关系** | **逐样本梯度重指派** | ✅ **唯一有效（平台 +3.52）**，且已达代码上限 1.0 |

**即：现有 SOTA 中不存在尚未试过、且能在本赛题约束下成立的机制。**

### 五、真正的瓶颈（建议后续投入的方向）

不是缺机制，而是**缺"鲁棒项"的本地代理指标**。鲁棒项是唯一 ~4.3 分缺口、且
**本地完全不可观测**的维度（hidden test + 私有标签），而本地 ASR 已被证明无法预测它
（第 44 轮：`jitter_villain` 本地 ASR 更差，平台分却更高）。

**可尝试的代理**：用 B 自己的底模在**公开发布的目标类 + 触发器样本**上测干净精度。
后门训练会压低这个量，所以它与 hidden test ASR 应当相关。若我能建立这个代理并
用 4 个已知平台分标定它，就能第一次在本地优化鲁棒项——那才是当前最大缺口的入口。

## 第 58 轮：用户防御建议文档的逐条判定 + `gradientClipQuantile` 实测（负结果）

用户提供了一份 A 侧防御机制建议文档（15 条候选）。逐条对照本项目已实现/已证伪的清单做判定，
并对其中**唯一尚未启用过的既有机制**做了实测。

### 一、实测新结果：逐样本梯度范数分位裁剪（`gradientClipQuantile`）为负

文档建议「归一化梯度：去掉逐样本范数，只传方向或量化后的值，可以挡住 norm 类推断」。
代码里**早有实现** `_clipGradients`（用逐样本范数的分位数作为上限，只对超过上限的样本按
`bound/norm` 缩放、保持方向不变），但我们一直用 `gradientClipQuantile: 0.0` **从未启用**。

实测（H 的基础上加分位裁剪，100 epoch，本地验证）：

| 场景 | N0（不裁剪）精度 / LRA | **N90（分位 0.9）精度 / LRA** |
|---|---|---|
| dataset_02_pmc | 0.9025 / 0.6972 | 0.8959 / **0.5110（到随机水平）** |
| dataset_03_pmc | 0.9448 / 0.5904 | 0.9087 / 0.5443 |
| dataset_02_composite | 0.8516 / 0.9102 | 0.6123 / 0.7574 |
| **dataset_03_villain** | 0.9638 / ASR **0.0673** | **0.5570 / ASR 1.0000** |

**判定：净负。** 隐私侧确实有效（`d02_pmc` 的 LRA 压到随机水平），但
- 精度损失 −0.0066 ~ **−0.2393**；
- **`d03_villain` 的 ASR 崩到 1.0000**，即后门完全得手、精度同时掉 0.407。

这是最不能接受的失败模式（后门放行 + 精度崩塌），已停止该实验。
**根因与前几轮一致**：任何对**统一梯度通道**的系统性改写都会破坏 VILLAIN 的训练。

| — | **代理损失梯度**（软标签 / 自蒸馏 / mixup 标签） | **结构性阻塞**：hook 拿不到 logits（`trainer.py:450-451` 的 logits/loss 在 hook 之外），无法构造替代损失 |
| — | **A-only 一致性检验**（冲突时回退 A-only 预测） | **结构性阻塞**：推理 hook 只收到两个嵌入（`trainer.py:175-204`），**拿不到 top model**，而 top model 在闭包里、hook 签名传不进去 |
| — | 梯度级别随机延迟 / 跨阶一致性打断 | **已实现**：逐样本重指派（随机置换）本身就破坏跨阶一致性，这正是它有效的原因 |
| — | 梯度随机丢弃部分样本 | **已实现**（重指派的退化形式）；`gradientShufflePoisonedOnly` 等门控覆盖 |
| — | 嵌入加噪 / 推理期多次采样投票 | 加噪族**已证伪**；投票需 top model，同上阻塞 |
| — | 轻量 DP 作为形式化兜底 | 加噪族**已证伪** |

### 三、文档给出的两条与实测一致的诊断（确认我们的方向）

1. **AMC 的放大发生在 B 本地 Adam 之前**，只作用于 `bottomB` 的原始梯度，A 看不到也管不了
   → 「检测梯度放大」这条路走不通。**与我们的实测一致**（所有基于梯度结构的全局门控都失败）。
   文档的结论是「防御必须在训练期完成：降低梯度中标签信息的**跨阶一致性**和信息量」
   —— **这正是逐样本重指派在做的事**（置换后相邻步的逐样本方向不再稳定对应）。

2. **后门触发器是固定常数写入**（`structuredDimensions` / `imageTriangle`）
   → 触发样本的嵌入形成低方差簇；触发器在 B 本地加入，A 只看到嵌入
   → 「防御要放在**嵌入的使用方式**上」。**与我们的观测一致**（`inferenceRepresentationHook`
   对 PMC/AMC 完全无效，因为补全攻击不经过它；而 `trainingRepresentationHook` 有效）。

3. **文档明确的信息论边界**：「如果 B 的特征本身就能预测标签，那么 B 用少量辅助标签推断标签
   就是信息论上无法完全消除的。防御目标应该是限制**超出特征相关性的额外泄露**」
   —— 这直接支持本项目已建立的 LRA 地板认知（`d02/amc` 基线自身就是 0.8897）。

### 四、由文档筛选出的**唯一新增可试项**

文档第 5 条「**对 B 做 party dropout**」是 15 条中**唯一尚未试过、且在本赛题可实现**的机制：

- 在 `trainingRepresentationHook` 里对某些样本把 `cutB` 整行置零（B 相当于缺席）；
- 顶模必须学会在缺少 B 时也能工作，从而**不过度依赖 B 的嵌入**；
- 机制上不同于梯度改写：它改变的是**顶模的学习压力分配**，而非梯度内容；
- 文档同时指出它「同时压低了 B 的后门杠杆」—— 即对鲁棒项也可能有益。

实现代价低（在既有 hook 内加一个逐样本伯努利掩码），且属于**结构性**机制（符合已验证有效的
那一类）。这是下一步应当测试的对象。

## 第 59 轮：party dropout 实测——对 PMC 有效、对 AMC 无效（新机制首次成功）

### 一、背景：这是从用户防御文档中筛出的唯一新增可试项

用户提供的 A 侧防御建议文档有 15 条候选。逐条对照本项目已实现/已证伪清单后（第 58 轮），
**只有第 5 条的「对 B 做 party dropout」是尚未试过且在本赛题可实现的**：

> 文档原文：「对 B 的嵌入做逐样本范数裁剪，**对 B 做 party dropout**，防止顶层模型过度依赖 B。
> 这些同时压低了 B 的后门杠杆。」

### 二、实现

新增 `_partyDropout`（`defense/purified_vfl.py`）：在 `trainingRepresentationHook` 内对随机
一部分样本把 `cutB` **整行置零**，使顶模必须学会在 B 缺席时也能工作。

参数：`partyDropoutRate`（默认 0.0）、`partyDropoutLabelInferenceOnly`（默认 true）。

它改变的是「**顶模被允许对哪些样本使用 B**」，而不是梯度内容——因此属于**已经验证能迁移到
平台的那一族**（结构性改变嵌入的使用方式），而非被证伪的加噪族。

单元验证：16 行、rate=0.5 → 置零 11 行；rate=1.0 → 至少保留 1 行；默认关闭不影响已交付配置。

### 三、实测（100 epoch，本地验证；PD0 = 不加 dropout 的对照）

| 场景 | PD0 精度 / LRA | **PD20（rate=0.2）精度 / LRA** |
|---|---|---|
| **dataset_02_pmc** | 0.9025 / 0.6972 | 0.8959 / **0.5039（随机水平）** |
| **dataset_03_pmc** | 0.9448 / 0.5904 | **0.9584（+0.0136）** / **0.5163（随机水平）** |
| dataset_04_amc | 0.8317 / 0.7606 | 0.8327 / **0.7606（完全不变）** |
| dataset_05_amc | 0.9893 / 0.4117 | 0.9845 / 0.4583（略变差） |
| dataset_03_villain | 0.9638 / ASR 0.0673 | **逐位不变** |

**结论：对 PMC（被动补全攻击）有效、对 AMC（主动模型补全）无效。**

- `dataset_02_pmc`：LRA 0.6972 → 0.5039（到随机水平），精度仅 −0.0066；
- `dataset_03_pmc`：LRA 0.5904 → 0.5163，**精度同时上升 +0.0136（双赢）**；
- AMC 两个场景几乎无效。

**原因与文档自己的诊断完全一致**：文档指出「AMC 的放大发生在 B 本地 Adam 更新之前，只作用于
`bottomB` 的原始梯度，A 既看不到也管不了」。AMC **主动**放大沿梯度稳定方向的标签信号，
而 party dropout 只降低 A 对 B 的依赖，**不改变 B 本地更新的方向一致性**，因此压不住 AMC。
PMC（被动补全）依赖 A 侧表征所保留的标签结构，所以会被 dropout 削弱。

### 四、途中修掉一个中止缺陷（两次复现）

首次全量运行在 `dataset_02_composite` 中止：

```
ValueError: LFBA cannot calculate L1 similarity from zero gradients
```

**根因**：dropout 把 `cutB` 整行置零 → 该样本的梯度**精确为零** → 而 LFBA 用逐样本梯度的
L1 相似度构建投毒集。

**第一次修复**（只在攻击批跳过）**不够**。第二次复现说明真正原因是：
**LFBA 在 `buildPoisonSet` 中排名的是上一 epoch 累积的梯度**，因此 dropout 在**其它批**留下的
零梯度行仍会被后续排名扫到。

**最终修复**：把 dropout **完全限制在纯标签推断场景**（要求 `backdoor == none`）。代价为零——
实测收益本来就只集中在纯 PMC 场景，而那些场景的 `poisoningActive` 恒为 False。

复验（`dataset_02_composite` + `dataset_01_composite` + `dataset_02_pmc`）：
复合场景不再崩且 dropout 不生效，纯 PMC 场景仍拿到 LRA → 0.5039。

## 第 66 轮：类内 + 类间双向压缩（带退火）——隐私项最大单次提升（+1.569）

### 一、机制

针对「B 用样本间关联性推断标签」，同时压缩类内差异与类间差异：

`
x -> x + pullback*(mu_c - x) + classPullback*(mu - mu_c)
`

mu_c 为类均值、mu 为批均值。两半正交可控（单元验证）：
仅 pullback=0.5 使类内散布 0.8778 -> 0.4389 而类间距离不变；
仅 classPullback=0.5 使类间距离 13.9325 -> 6.9663 而类内散布不变。

退火：classCollapseRampEpochs = R 时类间因子为 min(1, epoch/R)，
类内 pullback 自始满强度。故前 R 个 epoch 等价于「仅类内」变体。

### 二、三项分数（全量 40 场景）

| 变体 | 性能 | 隐私 | 鲁棒 | 合计 | 相对 O |

| cc_ramp100 | **17.748241** | **10.147274** | 17.113576 | **45.009091** | **+1.588930** |

- 隐私项 **8.578 -> 10.147（+1.569）**，本项目隐私项最大单次提升
