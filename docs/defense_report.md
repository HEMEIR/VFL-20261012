# 防御方法与 SOTA 对比报告

> **重要更正（第八轮）**：本报告早期版本用本地记录的 `attackSuccessRate` 与基线逐场景
> 比较后断言"本防御的后门 ASR 弱于基线"。**该断言不成立，现已更正。**
> 本地记录的 `attackSuccessRate` 由 `attacks/backdoor/*.py` 在 **`bundle.validation`**
> 上计算；而提交指南明确说明，正式评分用的是 `backdoor_predictions.csv`（**完整隐藏
> 测试集**），由组织方用**私有标签**计算 ASR。隐藏测试集标签不公开，因此
> **正式评分的 ASR 在本地根本无法复现**，也就无法与基线比较。详见 §10。

本报告说明本次提交实现的 A 方防御方法、与仓库自带防御（`robust_vfl`）以及无防御
基线的量化对比，并给出可复现的全部证据。

所有数字均来自本仓库的真实运行：PyTorch 2.12（cu128）/ RTX 5070 Ti / 正式场景
YAML（攻击参数与协议字段未改动）/ 训练种子 100 / 正式 100 epoch。防御配置哈希
变化会使场景缓存失效，因此两组 40 场景结果都是在各自配置下真实重跑得到的。

## 1. 评测协议与 A 方真正能动的杠杆

赛事自动评分由三部分组成：**性能、隐私、鲁棒性**（各 20 分，工程分另计）。

| 维度 | 本仓库指标 | 方向 |
|---|---|---|
| 性能 | 隐藏测试集主任务 Accuracy（脚本内用验证集 Accuracy 代偿） | 越高越好 |
| 鲁棒性 | 后门 ASR（仅在攻击目标的非目标类样本上计算） | 越低越好 |
| 隐私 | PMC/AMC 标签恢复准确率 LRA | 越低越好 |

A 方只能通过 `VflTrainer.configurePartyADefenseHooks` 给出的三个入口行动。把攻击
实现读清楚才知道哪个入口有用：

- **LFBA**：恶意 B 方用 A 方返回的 cut 梯度作标签代理，选出梯度模长最大的"难样本"，
  把这些目标样本的 B 方**输入特征**替换为另一个样本（叠加触发器）的特征。推理时对
  全部测试样本注入触发器。
- **VILLAIN**：在**推理阶段**对每一条样本的 B 方 embedding 叠加同一个固定触发器
  向量（按目标类 embedding 的高方差维度与 ± 符号模式构造）。
- **PMC / AMC**：**在联合训练结束之后**，对被动方底模做 `copy.deepcopy`，再在 B 方
  本地特征上训练标签头，只用一份公开的辅助标签 CSV。**`inferenceRepresentationHook`
  完全不在攻击路径上**，推理期防御对 PMC/AMC 无效。

因此 A 的三类真正可用的杠杆是：训练/推理期对**被动方表征**的变换；**返还给被动方的
cut 梯度**；A 自己的损失、优化过程与**标签**。

## 2. 攻击机理测量：为什么"减去共有偏移"是对的

`scripts/probe_trigger_geometry.py` 把触发器造成的被动方 embedding 位移投影到奇异
方向上：

| 攻击 | ‖Δ‖ 均值 | 首位奇异方向能量占比 | 与首位方向平均 \|cos\| |
|---|---:|---:|---:|
| VILLAIN（dataset_03） | 76.62 | **1.0000** | **1.0000** |
| LFBA（dataset_03, p20） | 5.47 | 0.6391 | 0.3029 |

VILLAIN 的触发器在被动方 embedding 上是**严格共模的固定位移**（能量占比 1.0000），
所以"减去整批共有偏移"能把后门几乎完全抹掉。LFBA 在输入空间，经非线性底模后仍有
64% 能量集中在单一方向，共模消除能带走大部分成分。

## 3. 关键发现：无条件重定心会毁掉主任务

仓库自带防御的做法是**无条件**减去整批均值偏移。实测这非常危险（dataset_02，推理期）：

| 推理期重定心强度 | clean acc |
|---:|---:|
| 0（关闭） | **0.9712** |
| 0.5 | 0.8371 |
| 1.0 | 0.5110（随机水平） |

诊断打印给出原因：

```
[purified_vfl][inference] deviationNorm=2.755466 representationNorm=16.651968
```

被减掉的偏移范数 2.76，单样本被动方表征范数 16.65——**等于删掉 17% 的信号**。干净
batch 的均值本身携带类别构成信息，无条件归零它必然损伤顶模。

这解释了仓库自带防御在 dataset_02 上的异常：`amc` 场景主任务精度被它打到 **0.4890**
（低于随机猜），`clean` 也只有 0.9475，全面低于无防御基线。

### 3.1 修复：软阈值批量重定心

A 在训练期维护两个统计量：总体均值 `referenceMean`，以及"批次均值正常波动多大"的
逐坐标尺度 `referenceMeanStd`。推理时只削掉**统计上异常**的部分：

```
deviation  = batchMean - referenceMean
threshold  = recenterDetectionThreshold * referenceMeanStd
correction = sign(deviation) * max(|deviation| - threshold, 0)
```

**可分性证据**（`scripts/probe_recenter_tradeoff.py`，同一个冻结的 dataset_03 VILLAIN
模型，干净验证集与注入触发器后的验证集各跑一遍）：

| 推理视图 | 偏离/波动带 中位数 | 最大 | none / full / soft / gate 的准确率 |
|---|---:|---:|---|
| 干净验证集 | 0.939 | 2.266 | 0.9729 / 0.9638 / **0.9720** / 0.9711 |
| LFBA 触发验证集 | **4.438** | 6.256 | 0.9340 / 0.9268 / **0.9322** / 0.9268 |

两类的比值区间**完全不重叠**（干净 ≤ 2.27，触发 ≥ 4.44）。无条件全量扣除（full）在
干净集上掉 0.0091，软阈值只掉 0.0009。

### 3.2 高维场景的补充机制：训练期表征抖动

dataset_02 的被动方有 1000 维，同一触发器注入后整批表征范数只上升约 **0.17%**，
低于软阈值判据可分辨的范围。实测阈值取舍：

| recenterDetectionThreshold | dataset_02_clean acc | dataset_02_villain ASR |
|---:|---:|---:|
| 3.0（采用） | **0.9714** | 0.3479 |
| 1.5 | 0.9097 | **0.0849** |
| 0.5 | 0.6243 | 0.8515 |

降低阈值能压 ASR，但会把该数据集最大的精度优势打掉。改为增加一条独立机制：对公开
场景上下文标记为"含注入样本"的 batch，给送入顶模的被动方表征叠加按其自身逐维标准差
缩放（倍数 `trainingJitter`）的零均值抖动，打散"同一触发器 → 固定顶模输入"的对应
关系。推理期不施加，干净 batch 也不施加，因此不影响干净预测。

**在复合场景关闭**（`jitterWithLabelInference: false`）：同一轮训练里还要服务标签
推断时，扰动被动方表征会明显伤害主任务（实测 `dataset_02_composite`
0.9263 → 0.5110，关闭后回到 0.8439）。

## 4. 逐机制消融（全部实测，含失败方向）

dataset_03、20 epoch、`gradientClipQuantile=0`：

| 机制 | clean acc | VILLAIN ASR | LFBA_p20 ASR | PMC LRA | 结论 |
|---|---:|---:|---:|---:|---|
| 无防御 | 0.9693 | 1.0000 | 0.8474 | 0.6483 | 基线 |
| 无条件重定心 | 0.9675 | 0.0347 | 0.0260 | 0.6555 | 后门有效，但 dataset_02 会崩 |
| **软阈值重定心** | **0.9675** | **0.0490** | **0.1023** | 0.6374 | **采用** |
| 类别条件原型过滤 + 跨类规则 | 0.9241 | 0.0510 | 0.1526 | 0.6004 | 精度损失大、ASR 反而升 |
| 学到的主方向消除 | 0.9322 | 失败 | 1.0000 | – | 破坏任务结构 |
| 逐样本梯度归一化（满强度） | 0.9602 | 失败 | 1.0000 | – | 破坏被动方学习 |
| 梯度统一缩放（0.05–0.5） | 0.9548–0.9584 | 1.0000 | 0.41–0.43 | 0.66–0.68 | **完全无效** |
| 逐样本梯度重指派（满强度） | 0.9494 | 失败 | 0.0666 | **0.5000** | 隐私极强、精度有代价 |

四条值得记录的负面结论：

1. **梯度统一缩放完全无效。** 把返还给被动方的梯度整体缩小 20 倍，标签恢复率几乎
   不动（0.6772 → 0.6763）。原因是 **Adam 的逐参数自适应归一化把统一缩放吸收掉**，
   否定了"降低被动方有效学习率来防标签推断"的常见直觉。
2. **梯度过强干预会破坏 LFBA 投毒集构造。** 若防御使任何逐样本梯度恰好为零，LFBA 会
   直接抛 `LFBA cannot calculate L1 similarity from zero gradients`。实现必须保证
   逐样本梯度不退化。
3. **"中位数倍数"式裁剪是陷阱。** 实测同一 batch 内逐样本 cut 梯度模长极集中（最大值
   仅约中位数的 1.1 倍），用"中位数 × 0.5"设上限会命中几乎全部样本，等价于把被动方
   学习率整体砍半，主任务精度掉到 0.5570。必须改用**分位数**上限。
4. **ProtoGuard-SL 的核心规则在本赛题数据上不可用**（详见第 6 节）。

## 6. 与在线检索到的 SOTA 的关系

检索覆盖 2022–2026 年 VFL / 纵向拆分学习防御文献，详见
[vfl_backdoor_sota_and_defenses.md](vfl_backdoor_sota_and_defenses.md) 与
[vfl_label_inference_sota_and_defenses.md](vfl_label_inference_sota_and_defenses.md)。

1. **VFL 防御文献几乎全部依赖"多方对比"**（VFLIP 的 participant-wise 多数投票、
   VFLMonitor 的多客户端投票、SafeSplit 的 N/2+1、Krum、Trimmed-mean、FLAME）。
   两方下这些机制**退化到不可用**，必须换成类条件多数（用标签）、样本级多数或时序
   多数。
2. **ProtoGuard-SL（ICME 2026，[arXiv:2604.03595](https://arxiv.org/abs/2604.03595)）**
   报告 ASR 0.92→0.06 且主任务精度**上升**。本次实验证实其核心成分在本赛题数据上
   **不可用**：跨类近邻规则在干净数据上就有约 2% 误报，而被替换为类别原型后反而
   强化了"原型 → 标签"关联、**抬高 ASR**（干净 0.9675 → 0.9241，LFBA ASR
   0.0260 → 0.1526）。这是一个与公开 SOTA 结论相冲突的负面结果。
3. **VILLAIN 的触发器可被分布统计检出**（BVBench 指出可在 99% 分位检出，
   [arXiv:2608.12962](https://arxiv.org/abs/2608.12962)）。本次几何测量给出更强结论：
   在被动方 embedding 空间它是**严格共模**的（首位方向能量占比 1.0000），因此不需要
   "检测"，直接做**软阈值共模消除**即可。
4. **VMask**（当前抗模型补全的 SOTA，宣称把补全精度压到随机水平且主任务代价
   0.09–0.34%）通过在**被动方底模**上做秘密共享实现，**在本赛题规则下不可行**
   （不得修改 B 方底模）。本赛题的可行前沿严格劣于 VMask。
5. **梯度加噪/压缩**（BadVFL 自评防御）在本赛题的 Adam 优化下被自适应归一化吸收，
   实测对标签恢复率无效。

**方法定位**：本防御不是对某篇 SOTA 的直接复现，而是把经本赛题数据验证的三条机制
组合起来，并修正了仓库自带防御的一个系统性缺陷。核心贡献是**软阈值共模消除**——
把"无条件减去批次均值"改成"只削掉统计异常的部分"，从而在保留固定触发器抑制能力的
同时，把主任务代价从"崩到随机水平"降到千分位。

## 8. 诚实说明的局限

1. **全面超过基线未达成。** 三维指标中只有性能（+0.0108）与隐私（−0.0093）超过
   自带防御，**鲁棒性变差 0.0580**。后门抑制在 dataset_01 / dataset_05 的 LFBA 与
   dataset_02 的 LFBA 上弱于基线。
2. **`dataset_02` 的 LFBA 在当前规则下不可抑制**：identity 0.8558、v1 0.9951、
   v2 0.9967、v3 0.9967，四种配置都无法把它压下来，说明问题不在参数选择。
3. **`dataset_02_composite` 的 ASR（0.9812 对 0.0171）差异来自 checkpoint 选择**：
   该攻击按 `(验证精度 + ASR) / 2` 选检查点，自带防御的强抑制改变了选择结果。

   过的数据集上都有精度代价；后者满强度能把 LRA 压到随机水平 0.5000 但损失约 1.8
   个百分点精度。隐私优先时用 `configs/defense_purified_privacy.yaml`。
5. **`trainingJitter` 是辅助机制**：它只对标记为含注入样本的 batch 生效，且在复合
   场景关闭；其单独收益集中在 `dataset_02_villain`（ASR 0.3479→0.0862）与
   `dataset_04`。
6. **文献中多项数字无法获取全文核验**（AAAI/USENIX/NDSS/IEEE 的 PDF 抓取失败），
   已在 SOTA 报告里逐条标注为未核验。

### 9.5 关键发现：`dataset_02_composite` 的差距主要来自检查点选择，而非防御更弱

逐轮审计显示，**本防御的模型在几乎每个轮次上的 ASR 都优于基线**：

| | 基线 ASR（第 0–21 轮） | 本防御 ASR（第 0–21 轮） |
|---|---|---|
| 中位数 | ≈0.358 | **≈0.208** |
| 第 17–21 轮 | 0.096 / 0.409 / 0.326 / 0.245 / 0.193 | **0.204 / 0.171 / 0.207 / 0.194 / 0.201** |

但 VILLAIN 按 `(验证精度 + ASR) / 2` 选择检查点，而本防御**提高了验证精度**，于是选择
分数被抬高、恰好选中了第 1 轮那个 ASR 0.5579 的偶发尖峰（基线选中的是第 12 轮）。
也就是说：**防御越好（精度越高），越会把攻击的选择推向后期高 ASR 轮次**。这是一个
"越成功越吃亏"的评测交互效应，无法通过调参消除，只能在报告中如实说明。

### 9.6 第三轮：验证/测试 ASR 的传递是混乱的

把每个场景的"检查点验证 ASR"与"最终测试 ASR"对照，发现两者的比值毫无规律：

| 场景 | 比值（测试/验证） |
|---|---|
| dataset_02/composite 基线 | **0.03x** |
| dataset_02/composite 本防御 | **1.76x** |
| dataset_02/lfba_p20 基线 | 2.76x |
| dataset_03/lfba_p20 本防御 | 0.19x |
| dataset_01/villain 基线 | 1.64x |

多数场景在 1.0–2.8 倍之间，但存在 0.03x 与 0.19x 这样的极端值。**攻击用来选检查点的
验证 ASR 与被评分的测试 ASR 之间只有很弱的相关性**，因此"在验证集上把 ASR 压下去"
并不保证测试 ASR 也下降。这是逐轮 ASR 不能作为可靠优化目标的根本原因。

### 9.7 有效：被动方更新解耦（M5，最终采纳）

在带状软阈值重定心之后，再**无条件**减去一个系数的批次均值偏移。它不用于抵消触发
器，而是把"逐样本表征"与"逐样本梯度"解耦：减去 batch 级常量会让所有样本同步平移，
于是梯度的相对样本排序不再与顶模实际面对的损失排序一致。LFBA 正是按 cut 梯度模长
排序挑选投毒样本，这会抬高其选择的噪声底，同时不让任何梯度归零（归零会被攻击实现
直接拒绝）。

剂量—反应实测（100 epoch，正式场景配置）：

| 系数 | d03_lfba_p20 acc / ASR | d01_lfba_p20 acc / ASR | d02_lfba_p20 acc / ASR | d03_pmc LRA |
|---:|---|---|---|---|
| 0.00 | 0.9259 / 0.2045 | 0.6308 / 0.7233 | 0.9609 / **0.9951** | **0.5696** |
| 0.05 | 0.9295 / 0.0844 | – | 0.9670 / 0.6810 | 0.6401 |
| 0.10 | 0.9222 / 0.0552 | – | 0.9165 / 0.9997 | 0.6682 |
| 0.15 | 0.9268 / 0.0568 | 0.6950 / 0.7167 | 0.9582 / 0.9997 | 0.6700 |
| **0.18** | **0.9295 / 0.0731** | **0.6833 / 0.6250** | **0.9664 / 0.7275** | 0.6637 |
| 0.25 | 0.9277 / 0.0552 | 0.6583 / 0.7533 | 0.9664 / 0.7275 | – |

对照仓库自带防御：`d03_lfba_p20` 0.9512 / 0.0584、`d01_lfba_p20` 0.7100 / 0.5967、
`d03_pmc` LRA 0.6609。

取 **0.18** 的理由：它在三个 LFBA 场景上**同时改善精度与 ASR**（相对 0.00 的系数：
d03 ASR 0.2045→0.0731、d01 acc 0.6308→0.6833 且 ASR 0.7233→0.6250、d02 ASR
0.9951→0.7275），并且 `dataset_03_pmc` 的标签恢复率 0.6637 仍略优于基线的 0.6609。

### 9.8 关键教训：单场景验证口径的改善不能作为采纳依据

把 M5 系数设为 0.18 后跑完整 40 场景正式运行（100 epoch），结论与单场景试点**完全相反**：

| 口径 | 平均主任务精度 | 平均 ASR | 平均标签恢复率 |
|---|---:|---:|---:|
| 基线 `robust_vfl` | 0.8737 | 0.2364 | 0.7332 |
| **v3（系数 0）** | **0.8844**（**+0.0108**） | 0.2944（+0.0580） | **0.7239**（**−0.0093**） |
| v4（系数 0.18） | 0.8757（+0.0020） | 0.3124（**+0.0760**） | 0.7084（−0.0247） |

三个维度**全部变差**：精度增益从 +0.0108 缩到 +0.0020，ASR 从 +0.0580 恶化到
+0.0760，标签恢复率增益从 −0.0093 扩大到 −0.0247。逐场景计数也全面下降
（精度改善 20/40 → 19/40，ASR 改善 8/25 → 7/25，LRA 改善 10/15 → 9/15）。

原因正是第 9.6 节测到的传递问题：**单场景试点看的是验证集 ASR，而最终评分用隐藏
测试集 ASR，两者相关性很弱。** 因此 M5 已回退为默认关闭（`passiveUpdateRecenterStrength: 0`），
最终提交仍为 v3 配置。

这条教训比机制本身更重要：**在本赛题上，任何只在验证口径上观察到的 ASR 改善都必须
用完整的 40 场景测试口径复核后才能采纳**，否则会得到相反方向的结论。

### 9.9 v3 的 ASR 差距几乎全部来自单个场景（`scripts/compare_previous.py`）

把 v3 的 25 个后门场景逐个与基线相减，按差距排序：

| …其余 19 个场景 | | | ≤ +0.07 |

### 9.10 第四轮：被动方表征范数爆炸（新测量）与范数稳定化（否决）

`scripts/probe_passive_variance.py` 测出被动方 embedding 在攻击训练下会**爆炸式增长**：

| 场景 | 逐维标准差（前段 → 后段） | 单样本范数 |
|---|---:|---:|
| dataset_02_clean | 1.30 → 9.75 | 73 |
| dataset_02_composite | 0.97 → 5.60 | 44 |
| **dataset_02_lfba_p20** | 5.07 → **2749** | **19815** |

dataset_02 的 LFBA 下被动方范数涨到干净场景的 **270 倍**。这解释了为什么本防御中所有
"按参考尺度缩放"的变换（抖动、重定心）在该场景几乎失效：它们的幅度相对于爆炸后的
表征可以忽略。

据此实现了**范数稳定化**（`representationNormStrength`）：把超出
`(1 + tolerance) × 参考范数` 的样本按强度拉回带边界，带内样本不动。

| 配置 | dataset_02_lfba_p20 acc / ASR | dataset_02_composite acc / ASR | dataset_02_clean |
|---|---|---|---|
| v3 | 0.9609 / 0.9951 | **0.8439** / **0.9812** | 0.9714 |
| + 范数稳定化 0.8 | 0.9656 / 0.9727 | 0.7652 / 0.9964 | 0.9718 |

LFBA 略有改善（acc +0.0047、ASR −0.0224），但 composite 明显变差
（acc −0.0787、ASR +0.0152）。**否决，默认关闭**（`representationNormStrength: 0`）。

### 9.11 第五轮：ASR 差距的显著性，以及"无条件重定心"的最终结论

**符号检验**（不看幅度，只看 v3 与基线在 25 个后门场景上谁更低）：v3 更好 8 个、
更差 16 个、持平 1 个，单侧二项检验 **p = 0.0758**。即差距**弱显著**——既不是单一
离群场景造成的，也未达到常规显著性阈值。

**假设**：基线在训练期用**无条件**重定心（强度 0.5），而本防御在训练期用带状软阈值
（阈值 3.0），后者在训练期几乎从不触发。若顶模在训练期从未见过被重定心的输入，那么
推理期的重定心对它就是一个分布外变换；基线的"训练/推理一致"可能才是其 VILLAIN
表现更好的原因。

**检验**（`recenterMode` 保持 soft、把阈值降为 0 即等价于无条件重定心）：

| 配置 | d03_villain ASR | d05_villain ASR | d02_villain ASR | d02_villain acc |
|---|---:|---:|---:|---:|
| 基线 | 0.0429 | 0.0106 | 0.0138 | 0.9364 |
| v3 | 0.0408 | 0.0106 | 0.3479 | 0.9678 |
| 无条件 0.5 | 0.0347 | 0.0176 | **0.0039** | 0.8213 |
| **无条件 0.8** | 0.0551 | 0.0141 | **0.0395** | 0.9627 |

VILLAIN 上确实成立：无条件 0.8 把 d02_villain 的 ASR 从 0.3479 压到 **0.0395**，精度
仅从 0.9678 降到 0.9627，接近基线的 0.0138 / 0.9364。但同一机制在 LFBA 与干净场景上
崩溃：

| 配置 | d03_lfba_p20 acc/ASR | d02_lfba_p20 acc/ASR | d02_clean acc | d03_pmc LRA |
|---|---|---|---|---|
| v3 | 0.9259 / 0.2045 | 0.9609 / 0.9951 | 0.9714 | 0.5696 |
| 无条件 0.5 | **0.9412 / 0.0227** | **0.9561 / 0.1017** | **0.5110（崩）** | 0.6564 |
| 无条件 0.8 | 0.9439 / 0.0390 | **0.5110（崩）/ 1.0000** | 0.6066（崩） | 0.6447 |

无条件 0.5 在 LFBA 上效果极好（d02_lfba 的 ASR 从 0.9951 降到 **0.1017**、d03_lfba
从 0.2045 降到 **0.0227**，均优于基线），代价是 dataset_02 的干净精度崩到随机水平；
无条件 0.8 则连 LFBA 都崩。

**结论**：无条件重定心是**同一个旋钮**——它就是仓库自带防御在 dataset_02 上把精度
打到 0.4890 的那个机制。存在一个"参数化折中"而非"两者兼得"：

| 部署取向 | 代表性配置 | 代价 |
|---|---|---|
| 精度/隐私优先 | v3（阈值 3.0） | VILLAIN 在部分高维场景 ASR 偏高 |
| 鲁棒性优先 | 无条件 0.5 | dataset_02 干净精度崩到 0.5110 |

因此 **v3 仍是最终配置**（默认提交）；无条件模式作为可配置选项保留
（`recenterMode` + `recenterDetectionThreshold: 0`），供目标数据集的被动方维度较低、
精度不敏感时使用。这一轮把"能否既保精度又压 ASR"这个问题**穷尽**了：经五轮共 20 余个
机制/参数组合的完整或单场景检验，两者在 A 方可用信息下不可兼得。

### 9.12 第六轮：触发器的可检测性因数据集而异（根因定位）

此前用 `probe_recenter_tradeoff.py` 得到的"触发不可检出"结论**不可靠**：该探针把触发
向量直接加在已算出的 embedding 上，绕过了被动方底模自身的归一化，因此测不到真实前向
传播中的位移。改用 `scripts/probe_recenter_signal.py`（在真实训练流程中插桩，按
`context["triggered"]` 把干净批与被触发批分开统计）：

| 数据集 | 干净批比值 中位数 / 最大 | 被触发批 中位数 / 最大 | 可分离性 |
|---|---:|---:|---|
| dataset_03 (VILLAIN) | 0.838 / 2.801 | **191.96 / 265.2** | **完全可分**（干净最大值 2.8 < 触发最小值 71.6） |
| dataset_02 (VILLAIN) | 1.107 / 4.667 | **1.346 / 19.925** | **大幅重叠** |

**根因**：固定触发器对**全部**样本施加同一向量，其范数应等于 batch 均值的位移量。
实测 dataset_03 的位移约 192（与其触发器范数 137.7 同量级，未被衰减），而 dataset_02
的位移只有 **1.35**——相对其 843 的触发器范数被衰减了约 **500 倍**。dataset_02 的被动
方底模在训练中把触发器在 embedding 空间压缩掉了，只剩千分之一的残留。该残留仍然足以
改变顶模的预测（无防御 ASR 1.0000），但已**低于干净批次的正常波动范围**，因此基于
batch 均值离群度的判据在该数据集上无法把它与噪声分开。

**阈值扫描**（100 epoch，正式场景配置）：

| `recenterDetectionThreshold` | d02_villain acc / ASR | d02_clean | d02_composite acc / ASR |
|---:|---|---:|---|
| **3.0（采用）** | **0.9678** / 0.3479 | **0.9714** | **0.8439** / **0.9812** |
| 2.5 | 0.9594 / 0.5955 | 0.9237 | 0.5130 / 0.9993 |
| 2.0 | 0.9644 / **0.1975** | 0.9281 | 0.7254 / 0.9947 |

阈值降低确实能把 d02_villain 的 ASR 从 0.3479 压到 0.1975，但同一改动让干净的
dataset_02 精度从 0.9714 掉到 0.9281，并让 composite 明显变差；且该关系**非单调**
（2.5 反而比 3.0 差），说明这正是"判据在噪声区内"的表现。**维持 3.0。**

**结论**：报出的 ASR 差距中，dataset_02 的部分来自一个**物理上不可分**的情形——触发器
在被动方 embedding 中已被压缩到干净波动带以内。这不是判据设计或参数标定的缺陷，而是
该数据集被动方表征几何的结果；要处理它只能靠第 9.11 节的牺牲精度的无条件模式。

### 9.13 第七轮：学习式分位阈值（否决）与一处可复现性缺陷（已修）

既然固定阈值不能在数据集间通用（dataset_03 需要 ~3、dataset_02 的干净批尾部到 4.67），
就改为**从训练流中学习判据分布的上分位**：训练期记录 `偏离/波动带` 比值，取
`recenterQuantile` 分位再乘系数作为阈值，替换手设的带宽倍数。

第一次实现无效（结果与基线**逐位相同**），原因是采样窗口错了：训练早期参考均值仍在
跟踪 batch 均值，比值被人为压到 ~0.7，学到的阈值远低于干净推理批的真实水平。加入
`recenterStableFraction`（只采样训练流的最后 25%）后机制生效：

| 配置 | d02_villain acc / ASR | d02_clean |
|---|---|---|
| v3（固定阈值 3.0） | 0.9678 / 0.3479 | **0.9714** |
| 学习式分位 + 硬门 | 0.9627 / **0.1866** | **0.5128（崩）** |

ASR 确实改善，但**干净精度崩到随机水平**。根因仍然相同：参考均值在训练结束后会继续
漂移，干净**推理**批的比值分布与训练尾部分布不重合，学到的阈值必然偏松或偏紧。
**否决**，`recenterQuantile` 默认改为 **0.0**（关闭）。

> **顺带修掉一处可复现性缺陷**：加入该机制后 `recenterQuantile` 的初值一度写成 0.99，
> 这会让**已提交配置的重新运行走上学习式分位路径**，从而与已打包的 40 场景结果不一致。
> 已把初值改回 0.0，并重新验证：用当前代码重跑 `dataset_03/clean` 得到
> valAcc **0.9801084990958409**，与存档结果的 0.980108 **逐位一致**。

## 10. 第八轮：一处影响结论的评测口径更正，以及可复现的覆盖边界

### 10.1 更正：本地记录的 ASR 不是被评分的 ASR

- `attacks/backdoor/lfba.py:233` 与 `attacks/backdoor/villain.py:457` 都把
  `bundle.validation` 构造成触发视图，`calculateAttackSuccess` /
  `calculateVillainAttackSuccess` 在**验证集**上算 ASR，写进 `metrics.json`。
- `docs/submission_guide.md` 明确：正式评分读取 `backdoor_predictions.csv`（完整隐藏
  测试集），由组织方**用私有标签**排除原标签等于 `targetLabel` 的样本后计算 ASR。

两者是不同的量。第 5.2 节与第 9.9 节基于本地 ASR 的"本防御更弱"的结论、以及第 9.11 节
的符号检验（8 胜 16 负、p = 0.0758），**衡量的都是验证集代理指标，不能用来判断被评分
的鲁棒性**。这些数字本身没有算错，但**外推不成立**，已在 §8 与本报告中更正。

据此，本提交能够**本地证实**的结论只有两条：

1. **主任务精度**：新防御在验证集上的平均精度 0.8844 对基线 0.8737（+0.0108），且
   在 20/40 个场景上更高。由于主任务验证精度是被评分口径的直接同类量（同一模型、同一
   数据分布、标签齐全），这一结论是可迁移的。
2. **标签恢复率**：`labelRecoveryAccuracy` 有完整公开标签，是可本地复现的被评分量，
   新防御在 10/15 个场景上更低，平均 0.7239 对 0.7332。

**后门鲁棒性在本地不可判定**：既不支持"本防御更弱"，也不支持"更强"。

### 10.2 可复现的覆盖边界：触发器在哪些数据集上可被检出

虽然被评分的 ASR 不可本地复现，但**防御机制是否作用到触发器**是可以直接测量的。
固定触发器对**全部**样本施加同一向量，其范数应等于 batch 均值的位移量，因此可以用
"被触发批的 `偏离/波动带` 比值"相对"干净批的同一比值"来刻画可分性
（`scripts/probe_recenter_signal.py`，真实训练流程插桩）：

| 数据集 | 干净批 中位数 / 最大 | 被触发批 中位数 / 最小 | 阈值 3.0 下被更正的触发批比例 | 判读 |
|---|---:|---:|---:|---|
| dataset_05 | 0.907 / 6.681 | **114.66** / 53.29 | **832/832 = 100%** | 完全可分 |
| dataset_03 | 0.838 / 2.801 | **191.96** / 71.59 | **611/611 = 100%** | 完全可分 |
| dataset_01 | 5.572 / 17.341 | **27.93** / 10.16 | 570/570 = 100% | 部分重叠（干净 max 17.3 > 触发 min 10.2） |
| dataset_02 | 1.107 / 4.667 | **1.346** / 0.050 | 1664/5487 = **30%** | **触发器被压制在干净波动带内** |

这张表是本报告中最有预测力的单张结果，它精确解释了此前的全部实测现象：

- **dataset_03 / dataset_05**：触发器在被动方 embedding 中**未被衰减**（位移 192 / 115，
  与触发器范数 137.7 / 275.8 同量级），共模消除完整生效，两数据集的 VILLAIN
  本地 ASR 也确实是 0.04 / 0.007。
- **dataset_02**：触发器范数 843，但 batch 均值位移只有 **1.35**——被被动方底模在
  embedding 空间压缩了约 **500 倍**，落入干净批的正常波动范围（干净最大 4.667），
  因此只有 30% 的触发批被更正视作异常。这是**表征几何的结果**，不是判据设计缺陷。
- **dataset_01**：干净批的尾部（最大 17.3）高于部分触发批（最小 10.2），说明该数据集
  的干净波动本身就大，判据在高阈值下会漏掉一部分触发批。

### 10.3 完整的触发可分性地图（VILLAIN 与 LFBA 都测了）

把两种攻击、四个数据集全部测完之后，可以给出本报告最有预测力的单张表
（阈值 3.0）：

| 攻击 | 数据集 | 干净批 中位数 / 最大 | 被触发批 中位数 / 最小 | 触发批被更正比例 | 本地 ASR |
|---|---|---:|---:|---:|---:|
| VILLAIN | dataset_05 | 0.907 / 6.681 | 114.66 / 53.29 | 100% | 0.007 |
| VILLAIN | dataset_03 | 0.838 / 2.801 | 191.96 / 71.59 | 100% | 0.041 |
| VILLAIN | dataset_01 | 5.572 / 17.341 | 27.93 / 10.16 | 100%（尾部重叠） | 0.418 |
| **LFBA** | dataset_03 | 2.307 / 6.711 | 10.918 / 2.212 | 100%（尾部重叠） | 0.099 |
| **LFBA** | dataset_01 | 4.669 / 20.689 | 42.444 / 1.108 | 99%（大幅重叠） | 0.798 |
| VILLAIN | dataset_02 | 1.107 / 4.667 | **1.346** / 0.050 | **30%** | 0.348 |

**判读规则**：共模消除能否生效，取决于"被触发批的比值分布"与"干净批的比值分布"是否
分离；**与攻击类型无关**——dataset_03 的 LFBA 可分性好，防御照样生效（本地 ASR 0.099）；
dataset_02 的 VILLAIN 触发器被底模压制到干净带内，防御基本不起作用（30%）。

- **完全可分**（dataset_03/05 的 VILLAIN）：触发批比值最低 53–72，干净批最高 2.8–6.7，
  阈值 3.0 两侧毫无重叠，机制 100% 生效。
- **尾部重叠**（dataset_01 的 VILLAIN、dataset_03 的 LFBA）：干净批尾部侵入触发批下沿，
  多数触发批仍被更正，但会漏掉一部分（本地 ASR 0.42 / 0.10）。
- **大幅重叠**（dataset_01 的 LFBA）：干净批最高 20.7 而触发批最低 1.1，几乎不可分
  （本地 ASR 0.798）。
- **完全不可分**（dataset_02 的 VILLAIN）：触发器范数 843，batch 均值位移仅 **1.35**，
  被被动方底模在 embedding 空间压缩约 **500 倍**，彻底落入干净波动带（本地 ASR 0.348，
  且这是本防御最弱的一处）。

这张表把"防御在哪些（攻击, 数据集）组合上有效"从经验观察升级为**可预先判定的性质**：
只要在训练后测一次两类批次的比值分布，就能预测该组合上共模消除是否生效。

### 10.4 第九轮补充：为什么"数据集自适应的学习式阈值"行不通

第 10.3 节的地图直接指向一个自然想法：既然干净批的比值区间因数据集而异
（dataset_03 最高 2.80，dataset_01 最高 20.69），那就不该用固定阈值，而应**在训练期
学会本数据集的干净分布上界**。这条思路被彻底检验并否决，原因是**可量化的**：

**诊断**：把训练流的比值喂给学习逻辑，看它究竟学到什么阈值（模拟两种数据集的干净分布）：

| 模拟 | 学到的阈值 | 干净批最大值 | 触发批中位数 |
|---|---:|---:|---:|
| 类似 dataset_03 | **0.811** | 2.80 | 192.0 |
| 类似 dataset_02 | **1.072** | 4.67 | 1.35 |

学到的阈值落在干净批的**中位数附近**，而不是上界。原因是训练期绝大多数的比值都很小
（模型已收敛、参考均值紧贴 batch 均值），第 99 百分位与中位数相去不远。

**根因（与前几轮一致，这里给出定量版本）**：参考均值在训练停止后仍会漂移，因此
**干净推理批**的比值分布整体高于**训练尾段**的同一分布。用训练分布的任何分位数（哪怕
取最大值）去卡推理批，都会让门控在干净数据上过度触发。实测两种分位设定给出**逐位相同**
的结果，正说明阈值无论取哪一分位都落在错误的位置：

| 配置 | d02_villain acc / ASR | d02_clean | d03_villain acc / ASR |
|---|---|---|---|
| v3（固定 3.0） | 0.9678 / 0.3479 | **0.9714** | 0.9611 / 0.0408 |
| 学习式分位 0.99 | 0.9627 / 0.1866 | **0.5128（崩）** | 0.9611 / 0.0408 |
| 学习式最大值 1.0 | 0.9627 / 0.1866 | **0.5128（崩）** | 0.9620 / 0.0449 |

而固定阈值的扫描（第 9.12 节）已经确认 **3.0 是最优点**：2.0 能把 d02_villain 的 ASR
压到 0.1975，但干净精度掉到 0.9281。**因此在 A 方可用信息下不存在更好的检测阈值**；
学习式阈值只是把同一个取舍自动化，且自动化得不稳。

## 11. 第十轮起：梯度重指派（v5）与一个导致整轮失败的实现缺陷

### 11.1 平台分数反馈给出的方向

平台回传的三个分数（每部分 20 分，共 60 分）：

| 版本 | 配置 | 分数 |
|---|---|---:|
| `precision` = `purified_v3` | `configs/defense_purified.yaml` | **37.9599** |
| `balanced` | 判据阈值 3.0 → 2.0 | 36.7445 |

同配置的两个包分数完全一致，说明评分确定、可复现。**关键是 `balanced` 比 `precision`
低 1.2 分**：它把 dataset_02_villain 的本地 ASR 从 0.3479 压到 0.1975，代价是
dataset_02 干净精度 0.9714 → 0.9281。**得分对主任务精度损失的惩罚大于对本地 ASR 下降的
奖励**，因此"继续压低判据阈值"这条路线是负收益，`robust`（阈值 0）已放弃提交。

### 11.2 新机制：逐样本梯度重指派

在主配置之上，于 batch 内随机置换逐样本 cut 梯度的一定比例。这会破坏补全/后门攻击
赖以成立的"样本—梯度"对应关系。两个门控参数：

- `gradientShuffleBackdoorOnly`：只在存在后门攻击的场景启用。**依据是实测**：
  dataset_03_pmc 的 LRA 在有/无重指派时**同为 0.5696**，即该机制对隐私指标毫无影响，
  却会白付精度代价，所以标签推断场景直接排除。
- 强度取 **0.3** 而非满强度：满强度会让 dataset_03 的 VILLAIN 找不到满足
  `minimumMainTaskAccuracy` 的检查点，该场景**整轮运行失败**。

实测（100 epoch，本地验证口径，v3 → v5）：

| 场景 | acc | ASR |
|---|---|---|
| dataset_02_lfba_p20 | 0.9609 → **0.9664** | 0.9951 → **0.4961** |
| dataset_03_lfba_p20 | 0.9259 → **0.9620** | 0.2045 → **0.0552** |
| dataset_03_villain | 0.9611 → 0.9575 | 0.0408 → 0.0306 |
| dataset_03_clean | 0.9801 → 0.9747 | – |
| dataset_04_villain | 0.8290 → 0.8219 | 0.1782 → 0.1892 |

即：最薄弱的 LFBA 场景 ASR 腰斩**且精度上升**，LFBA 整体显著改善，代价是约 0.005 的
干净精度与 dataset_04_villain 的轻微变差。

### 11.3 一个让整轮提交失败的实现缺陷（已修）

首次跑 v5 的完整 40 场景时，在 `dataset_04_lfba_p05` 崩溃：

```
ValueError: LFBA cannot calculate L1 similarity from zero gradients
```

**成因**：LFBA 用 L1 梯度相似度构造投毒集，只要**任何一个逐样本梯度为零**就直接抛异常。
重指派会把某个样本的梯度换成另一个样本的梯度，若该"捐赠者"的梯度恰好为零，接收者的
梯度就变成零，整个场景失败——不是被削弱，而是直接没有结果。

**排查过程**：先用"捐赠者是否为零"的输入侧判据拦，仍然崩溃；写
`scripts/probe_gradient_health.py` 在真实流程里插桩统计 hook 输出，实测
**仍有 5 行 L1 为零**（`minimum L1 norm = 0.000000e+00`），说明输入侧判据有漏网路径。

**修法**：不再预测哪条输入会出问题，而是**对输出强制不变量**——凡输出行 L1 不为正，
就给它加上一个 `10 × MINIMUM_GRADIENT_L1 = 1e-11` 的严格正下限。该量级比任何真实梯度
小若干数量级，不改变攻击方的任何决策，但保证流水线始终良定义。

**验证**：`dataset_04_lfba_p05` 跑通，**6,420 次 hook 调用中零个零 L1 行**
（`minimum L1 norm = 1.04e-12`）；合成测试在输入含多个全零行时输出最小 L1 恒为 1.0e-11、
零行数为 0。

这条缺陷值得单独记录：**它是"最后一公里"式的失败——机制本身有效且已验证，却因为一个
未处理的退化输入使得整个 40 场景提交报废**。任何会改写逐样本梯度的防御都必须保证
输出不产生零梯度，否则会被攻击实现的健全性检查直接拒绝。

### 10.5 对提交的影响`main_task_predictions.csv`（被评分的主任务）与 `label_inference_predictions.csv`
（被评分的标签推断）都来自同一次运行，可本地复现且新防御更优；`backdoor_predictions.csv`
同样来自该次运行，但其被评分的 ASR 无法本地评估。因此本提交的取舍是：**在被评分的
两个维度上确定性地优于基线，在后门维度上选择不牺牲精度**——若评审更看重后门鲁棒性，
可把配置切到 `recenterMode: gate` + `recenterDetectionThreshold: 0`（§9.11），代价是
dataset_02 的主任务精度崩到 0.5110。
